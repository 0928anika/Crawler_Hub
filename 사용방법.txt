Crawler Hub — GitHub 협업용

공유할 기본 구성은 다음과 같습니다.
  Crawler_Hub.bat                 실행 파일 (최상위)
  사용방법.txt
  브랜드_크롤러_제작프롬프트.txt (자동 색상 매핑용)
  브랜드_크롤러_제작프롬프트_수동색상매핑.txt (사용자가 사진 색상을 지정하는 브랜드용)
  브랜드_크롤러_제작프롬프트_이미지저장.txt (로컬 크롭·이미지 파일명 출력용)
  app/                            공통 프로그램·화면·템플릿
  brands/                         브랜드별 Python 코드와 개별 JSON

1. GitHub에서 검증한 버전을 내려받아 같은 폴더 구조로 준비하세요. 개발용 저장소는 일반 로컬 폴더 사용을 권장합니다.
2. 최상위 Crawler_Hub.bat를 더블클릭하세요. Python 3.10 이상이 필요하며 처음에는 필요한 패키지를 자동 설치합니다.
3. 관리자 → 새 브랜드에서 메모·브랜드 정의·Python 코드를 등록하세요. 현재 등록된 브랜드와 코드가 포함되어 있습니다.
4. 새 브랜드 ID가 my_brand라면 brands/my_brand.py에 코드가, brands/my_brand.json에 정의와 메모가 저장됩니다. 관리자가 코드 해시도 함께 갱신합니다.
5. 저장 후 GitHub Desktop에서 변경 내용을 커밋하고 업로드하세요. 다른 PC는 검증한 버전을 받은 뒤 앱을 재실행하세요. 운영본에서는 직접 코드를 수정하지 않습니다.
6. Playwright 브라우저가 필요한 브랜드는 Crawler_Hub.bat --install-browser 를 실행하여 브라우저를 추가 설치할 수 있습니다.

결과·입력·로그·작업 이력·런타임·관리자 백업은 각 PC의 %LOCALAPPDATA%\CrawlerHub에만 저장합니다. 공유폴더에는 저장하지 않습니다. 과거 프로그램의 로컬 작업 이력은 최초 실행 시 로컬에서 보존 복사합니다. 이어하기는 입력 한 행 단위이며 완료 행은 건너뛰고 중단 행은 다시 수집합니다.

관리자 메모는 브랜드 정의 위에 있습니다. 메모만 저장 또는 코드와 함께 저장을 사용할 수 있습니다. 각자 작업 브랜치에서 편집하고 PR로 변경 내용을 합치세요.
브랜드 정의 script는 my_brand.py처럼 파일명만 지정합니다. 새 Python 코드는 PORTAL_API_VERSION = 1 / crawl(ctx) 실행 계약을 유지합니다. 이는 크롤러 호환성 식별자입니다.

브랜드 등록 시 상단 네 칸은 브랜드 ID / 브랜드명 / 카테고리 / 크롤링 소스입니다. 소스는 공식 홈페이지, 네이버 브랜드스토어, 네이버 NC_YS처럼 자유롭게 적습니다. 브랜드명에는 괄호를 붙이지 않아도 화면에 자동으로 브랜드명 (소스)로 표시됩니다. 같은 브랜드라도 소스마다 다른 ID로 등록하세요. 예: egoist_official, egoist_nc_ys.

수동 색상 매핑 (로엠 샘플)
새 크롤링에서 로엠 (공식 홈페이지)을 고르고 기본 품번을 입력합니다. 모든 새 작업은 실제 공식몰에서 수집합니다. 수집 결과 Excel은 URL당 한 행입니다. 검수/모니터/작업 이력의 색상 매핑하기를 누르면 모든 품번이 구분된 세로 화면으로 표시됩니다.
품번별 색상을 선택하고 사진 전체를 클릭한 뒤 선택 저장을 누릅니다. 색상 하나 또는 마지막 남은 색상에는 남은 사진 모두 선택 버튼이 표시됩니다. 잘못 섞인 사진은 다시 클릭하여 해제하세요. 색상에 사진 0장을 저장하면 그 색상은 결과에서 제외됩니다. 어느 색상에도 선택하지 않은 사진은 버립니다. 모든 색상을 사진 0장으로 저장한 품번은 최종 결과에서 제외됩니다.
중간 저장하고 나가기는 다른 색상/품번의 아직 저장하지 않은 선택도 로컬에 저장합니다. 나중에 같은 작업의 색상 매핑하기로 이어서 편집하세요. 브라우저를 직접 닫으면 미저장 선택에 대해 브라우저 확인이 표시되므로 가능하면 중간 저장하고 나가기를 사용하세요.
모든 색상을 저장한 뒤 매핑 완료를 누르면 결과 Excel을 색상당 한 행으로 재구성합니다. 원래 갤러리 순서의 첫 사진이 대표, 나머지 사진으로 추가 5슬롯을 채웁니다. 추가가 부족하면 선택한 사진만 반복하고 쉼표로 연결합니다. 기존 원본 URL 행과 매핑 기록은 각 사용자 로컬에 보존되며 공유되지 않습니다.

색상 매핑: 브랜드 카드의 [색상 매핑 필요] 배지를 확인하세요. 같은 품번의 여러 상품 링크에서 모은 사진과 색상은 한 카드에 합칩니다. 옵션 추가로 색상명/코드를 직접 입력하고 ×로 삭제할 수 있습니다. 옵션 초기화는 수집한 원래 색상을 복구하고 수기 옵션을 제거합니다. 선택은 중간 저장하고 나가기로 로컬에 보관됩니다. 완료 후 [✓ 매핑 완료 · 수정]으로 다시 편집할 수 있습니다. 대표이미지는 선택 사진의 첫 컷, 추가이미지는 나머지 최대 9장(부족하면 5장까지 반복)입니다. 상세는 수집한 공통 HTML을 모든 색상에 동일하게 적용합니다. 이전 작업에서 수집하지 않은 상세는 새로 수집해야 합니다.

시작 화면은 새 크롤링입니다. 대시보드는 제공하지 않습니다. 수동 색상 매핑용 제작 프롬프트는 해당 파일 전체를 다른 AI에 전달하고, 맨 위 브랜드 정보·URL·시험 품번을 작성해 사용하세요. 답변의 JSON은 브랜드 정의, Python은 크롤러 Python 코드에 각각 붙여넣습니다.

추가 결과 열: 크롤러 record에 {"원본 상품명": "사이트 원문"}처럼 표준 필드 외 키를 넣으면 결과 Excel의 표준 열 뒤에 자동 보존합니다. output_headers에 미리 선언해도 됩니다. 행/품번마다 열이 달라도 이름 기준으로 정렬하며 없는 값은 빈 셀입니다. 수동 색상 매핑 후에도 유지되고, 선택 사진에 서로 다른 원본 값이 있으면 줄바꿈으로 함께 기록합니다. 검수의 추가 수집 정보와 원본 데이터에서도 확인할 수 있습니다. 새 SDK 규약은 새로 시작하는 작업부터 적용됩니다.

수동 색상 매핑 결과 재구성은 수집에 성공한 입력 행만 대상으로 합니다. 실패·미완료 입력 행은 부분 사진이 있어도 매핑 후보/최종 결과에서 제외하며, 다른 성공 품번의 완료를 막지 않습니다. 같은 품번의 별도 성공 입력 행이 있다면 그 행에서 수집한 자료만 사용합니다. 제외된 행의 상태·오류는 작업처리로그에 남고, 추후 재실행할 수 있습니다. 저장한 성공 품번의 선택은 유지됩니다.

상품 링크는 품번·상품명·색상과 함께 필수 결과입니다. 현재 등록된 네 브랜드 코드에 실제 상세 링크 수집을 적용했습니다. 수동 매핑 최종 행은 동일 품번의 첫 번째 수집 성공 상품 링크를 모든 색상에 동일하게 사용합니다. 기존 작업에 링크가 저장되지 않았다면 새 수집 작업이 필요합니다. 기존 작업의 이어하기는 당시 보관한 크롤러 버전을 사용합니다.

이미지 저장 유형
브랜드 정의에 image_mode: "local", mapping_mode: "manual"을 지정합니다. ‘이미지 저장’ 배지가 표시됩니다. 제작 프롬프트는 브랜드_크롤러_제작프롬프트_이미지저장.txt입니다.
크롤러는 ctx.save_image로 개별 컷을 저장한 뒤 ctx.emit_local_image로 실제 색상 후보와 전송합니다. 실제 라벨 인식 등 근거가 있으면 mapped_color/mapping_evidence로 사전 매핑할 수 있습니다. 허브에는 OCR 엔진이 내장되어 있지 않습니다.
웹에서 사전 매핑을 확인·수정하거나 미매핑 사진을 색상별로 선택합니다. 중간 저장 후 나가기도 지원합니다. 완료 시 대표 품번_색상코드.jpg, 나머지 _02.jpg부터 파일을 생성합니다. 색상코드가 없으면 색상명을 사용합니다. 대표/추가 Excel 셀에는 URL 대신 파일명이 들어갑니다. 최대 대표 1장+추가 9장, 추가가 부족하면 선택된 파일명을 반복해 5칸을 채웁니다.
완료 후 결과 검수의 이미지 폴더 열기 또는 이미지+엑셀 ZIP을 이용하세요. ZIP에는 result.xlsx와 images 폴더가 함께 들어갑니다. 그 images 폴더의 파일을 WING에 업로드하고 같은 엑셀의 파일명을 사용합니다. 원본 크롭은 각 PC의 작업 폴더에 보존하고 매핑 재구성은 별도 등록용 폴더로 생성하여 덮어쓰기 충돌을 막습니다.

등록용 폴더 변경(v0.8.1): 대표이미지/와 추가이미지/ 두 폴더 각각에 모든 품번의 해당 JPG를 바로 모읍니다. 품번별 하위 폴더는 없습니다. 결과 검수에서 대표이미지 폴더 열기 / 추가이미지 폴더 열기 버튼을 사용하세요. ZIP에도 두 폴더 구조가 유지됩니다. 웨스트우드 등록용 정의는 additional_image_count=5이며 대표 외 컷이 없으면 대표를 추가 폴더에도 복사하고 파일명을 5번 반복합니다. 기존 완료 결과는 색상 매핑의 결과 다시 저장으로 새 폴더를 생성할 수 있습니다.

웨스트우드 공통 상세이미지(v0.8.2): 색상명·상품사진 → 제품 세부이미지 → PRODUCT INFO·SIZE 세 원본 영역을 순서대로 합칩니다. 등록용 상세이미지/품번.jpg로 저장하고 같은 품번의 모든 색상 행에 동일한 파일명을 출력합니다. 결과 검수의 상세페이지 탭과 상세이미지 폴더 열기 버튼으로 확인하세요. 원본 출처와 권리안내는 파일 메타데이터/추가 열로 보존됩니다. 새 상세이미지 방식은 새 작업부터 수집되며 기존 HTML 결과를 자동 변환하지 않습니다.

최종 상세 구성: 색상명+해당 상품사진(원래 순서) → 제품 세부이미지 → PRODUCT INFO+SIZE. 세 영역을 모두 포함합니다. 파일명은 품번.jpg이며 색상코드를 붙이지 않습니다.

이미지 저장 경로 보완(v0.8.3): Windows 앱 저장소의 긴 경로에서 임시 JPEG 파일명이 길어져 저장에 실패하던 문제를 수정했습니다. 짧은 임시 이름과 긴 경로용 파일 I/O를 사용합니다. 수정은 새로 시작하는 작업부터 적용됩니다. 기존 실패 작업은 당시 worker 사본을 사용하므로 새 작업을 시작하세요.
