# Windows 공개 develop 업데이트

`Crawler_Hub_Update_Windows.bat`를 기존 `Crawler_Hub` 폴더에 넣고 실행합니다.
`tools/update_develop.py`도 함께 있어야 합니다. 최초 도입 시 두 파일을 한 번 복사하거나
이 파일들이 포함된 새 배포본을 사용하세요. Git 설치·GitHub 로그인·토큰은 필요 없습니다.
Python 3.10 이상이 필요하며 기존 허브의 Python 환경을 우선 사용합니다.

1. 앱 창/실행 콘솔을 종료합니다. 브라우저 탭만 닫으면 서버는 남을 수 있습니다.
2. 업데이트 BAT를 실행하면 공개 `0928anika/Crawler_Hub`의 최신 `develop` 커밋을 확인합니다.
3. 해당 커밋 SHA의 ZIP을 내려받아 브랜드 코드 해시와 앱/브랜드 Python 문법을 검사합니다.
4. 정상일 때 `app`, `brands`, `tools`와 기존 앱 실행기를 교체합니다.
5. 완료 후 기존 실행 BAT로 앱을 다시 실행합니다. 수정 크롤러는 새 수집 작업으로 확인합니다.

이는 BAT를 실행할 때 업데이트하는 기능입니다. 주기 실행/앱 실행 시 자동 검사는 등록하지 않습니다.
자동으로 실행 중인 수집을 중단하거나 앱을 강제 종료하지 않습니다.
개발용 Git 폴더에서는 덮어쓰지 않고 중단합니다. 개발자는 `git pull`을 사용하세요.

## 보존 및 복구

- `%LOCALAPPDATA%\CrawlerHub`(또는 `CRAWLER_HUB_HOME`)의 작업·설정·결과·가상환경은 수정하지 않습니다.
- 설치 폴더 바로 아래의 `jobs`, `settings.json`, 기타 사용자 파일도 교체하지 않습니다.
- `app`/`brands`/`tools` 안에 작업/설정 파일이 있거나 사용자 데이터 경로가 그 안으로 지정돼 있으면 중단합니다.
- 변경 전 소스는 설치 폴더의 `.crawler-update-backups/<시각_커밋>/`에 보존합니다.
- 일부 파일 교체 중 오류가 나면 이미 바뀐 소스를 이전 파일로 되돌립니다.
- 나중에 수동 복구하려면 앱 종료 후 백업의 앱/브랜드/도구/실행기를 같은 위치로 되돌리세요.
- 사용자가 직접 수정/추가한 브랜드는 최신 공식 브랜드 폴더로 교체되며, 기존 파일은 백업에 남습니다.
- 기존 작업의 실행 사본은 업데이트하지 않습니다. 기존 이력은 그대로 열 수 있습니다.
- 동시 업데이트는 잠금 파일로 막습니다. 강제 종료 후 잠금이 남으면 업데이트 프로세스가
  끝난 것을 확인한 뒤 `.crawler-update.lock`만 지우고 재실행하세요.

공개 저장소만 지원합니다. 회사 네트워크에서 GitHub/API/codeload가 차단되거나 다운로드가
실패하면 적용하지 않습니다. 원격 SHA는 다운로드 중 버전 혼합을 막기 위한 고정 기준이며,
검토/승인된 릴리스나 별도 코드 서명을 의미하지는 않습니다.

다운로드/검증만 확인할 때는 `Crawler_Hub_Update_Windows.bat --check-only`를 실행합니다.
Git 작업 폴더에서도 검사 모드는 가능하며 설치 소스를 교체하지 않습니다.

검증 기록: 공개 develop SHA 고정 다운로드와 앱/브랜드111개 검증 성공.
업데이트 전용 테스트10개로 사용자 데이터 보존, 중간 실패 복구, 실행 중 차단,
Git 개발폴더 보호, ZIP 경로/해시/문법 검증 및 동시 실행 잠금을 확인했습니다.
