# Windows 공개 develop 업데이트 v3

Git 설치·GitHub 로그인·토큰 없이 공개 develop을 받습니다. Python 3.10 이상이 필요합니다.

## 설치와 실행

이번 버전 최초 적용은 `Update.bat`과 `tools/update_develop.py` 두 파일을 수동 교체하세요.
이전 도구는 업데이트 도구 자체를 내려받지 않으므로 한 번은 수동 교체가 필요합니다.
기본 배치는 루트의 Update.bat + tools/update_develop.py입니다.
설치 폴더 아래 임의 하위 폴더에 Update.bat과 update_develop.py를 함께 두는 배치도 지원합니다.
교체 대상인 app/brands 안에는 두지 마세요.
폴더 이름·숨김은 접근 제어가 아닙니다. 필요한 경우 별도 Windows 폴더 권한을 설정하세요.

앱 콘솔을 종료한 뒤 BAT를 실행하면 업데이트 성공 또는 최신 확인 후 앱을 바로 실행합니다.
실패하면 앱을 자동 실행하지 않고 오류를 보여줍니다. 실행 중 작업을 강제 종료하지 않습니다.
`Update.bat --no-launch`는 업데이트만, `Update.bat --check-only`는 다운로드·검증만 수행합니다.
Python 파일 직접 실행은 업데이트만 수행합니다.
Python 후보마다 3.10 이상인지 확인하여 오래된 가상환경만 발견됐다고 바로 실패하지 않습니다.

## 갱신 범위

- app/ 전체, brands/ 전체
- Crawler_Hub_Windows.bat, Crawler_Hub_Mac.command
- Update.bat, tools/update_develop.py 두 업데이트 파일
- 하위 폴더에 배치한 경우 실제 사용 중인 업데이트 파일 쌍도 함께 갱신

실행 중인 BAT는 직접 덮어쓰지 않고 `.new`로 보관한 뒤 다음 BAT 실행 시작 시 적용합니다.
Python 업데이트 파일은 백업·교체에 포함하며, 교체 실패 시 앱·브랜드와 함께 복구합니다.
그 외 tools 파일·문서·프롬프트·테스트는 갱신 대상에 포함하지 않습니다.
Git 개발 폴더는 실제 적용을 막습니다. 개발자는 git pull을 사용하세요.
검사 전용 --check-only는 Git 폴더에서도 가능합니다.

## 검증과 표시

develop의 커밋 SHA를 확인하고 해당 커밋 ZIP을 받습니다.
브랜드 JSON/Python 해시·ID와 Python 문법을 교체 전에 검사합니다.
같은 커밋이고 로컬 관리 파일의 내용도 그대로면 ZIP 다운로드와 교체를 생략합니다.
실행 중 앱은 Crawler Hub 페이지와 설치 경로·실행 사본 경로를 확인해 감지합니다.
다른 프로그램의 server.py라는 이름이나 같은 포트 사용만으로 차단하지 않습니다.

변경 내역 예: `앱 변경 6개 / 브랜드 추가 1개 / 브랜드 수정 3개 / 브랜드 제거 0개`
앱은 추가·수정·삭제된 파일 수, 브랜드는 ID별 개수입니다.
JSON과 Python이 둘 다 바뀌어도 브랜드 수정은 1개입니다.

## 백업과 데이터 보존

업데이트 직전 파일은 설치 폴더의 `.crawler-update-backups/시각_커밋번호/`에 보관합니다.
이번 버전부터 정상 완료 표시가 있는 백업만 최근 5개를 자동 보관합니다.
표시가 없는 옛 백업·수동 백업·실패 시 남은 백업은 자동 삭제하지 않습니다.
백업 정리 실패는 경고만 표시하고 이미 성공한 업데이트를 실패로 바꾸지 않습니다.
작업·설정·결과·브라우저 프로필·가상환경은 갱신하지 않습니다.
로컬에만 추가한 app/brands 파일은 새 실행 폴더에서 빠지고 백업에 남습니다.
삭제·이름 변경된 브랜드가 새 목록에 중복으로 남지 않습니다.
수정된 크롤러는 새 수집 작업으로 확인하세요.

동시 업데이트는 운영체제 파일 잠금으로 차단하며 강제 종료 시 잠금은 자동 해제됩니다.
.crawler-update.lock 파일이 남아 있어도 실행 중이라는 뜻은 아니며 수동 삭제할 필요가 없습니다.
주기 실행이나 앱 시작 시 자동 업데이트는 등록하지 않습니다.
공개 저장소만 지원합니다. 해시 검증은 코드 서명이나 회사 승인 릴리스라는 뜻은 아닙니다.

## 참고한 방식

Oberon의 업데이트 후 앱 실행, 실행 중 BAT를 .new로 받는 방식, 변경 개수 표시를 참고했습니다.
기존 검증 후 폴더 교체·백업·실패 복구는 유지하고 두 업데이트 파일을 함께 관리하도록 적용했습니다.
