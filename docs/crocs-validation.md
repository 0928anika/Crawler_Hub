# 크록스 공식몰 크롤러

## 최종 사용자 지정 기준

화면에 표시되지 않더라도 공식 SKU의 기본 품번·색상 연결이 확인되면 수집한다. 현재 화면 색상만으로 제한했던 정책은 철회했다. masterProductId, variants.productId의 기본품번-색상 접두사, variationValues.color를 대조한다. 따라서 11016은 공식 연결된 19색상을 대상으로 한다.

리뷰/UGC/라이프스타일 사진은 제외한다. 공식 카탈로그 촬영 역할이 확인된 ALT100(옆면), 110(한쌍), 120(상단), 130(바닥면), 140(사선), 160(뒷면)만 후보로 사용한다. 문제의 ALT210 및 그 밖의 역할 미확인 컷은 다운로드부터 제외한다. 품번별 사진/해시 허용목록이 아니라 공식 갤러리 촬영 역할 기준이다. 고해상도 주소는 실제 화면의 공식 렌더러와 정확한 공식 색상 asset ID를 연결하고 공개 GET/실제 파일 검사를 다시 거친다. 다른 색상의 asset ID를 복사하지 않는다. 이 규칙은 완전한 시각 인식이나 모든 UGC의 원저작자 판정을 보장하지 않는다.

아래는 변경 경위와 이전 검증 기록이며 위 최종 기준이 우선한다.

최종 기준 실제 Hub worker 검증: 11016 19색상/exit 0, 약 24초. 19행 모두 ALT210 미포함이며 펄핑크/와일드오키드(6MB)는 ALT120 정상 카탈로그 컷이 대표로 선택됐다. 푸크시아/블랙(950), 터메릭(7AG)은 유효한 카탈로그 사진이 확인되지 않아 이미지 빈칸과 확인 필요 상태를 유지한다. 공식 SKU 대조 및 리뷰 차단 회귀 테스트 8개 통과.

## 이전 기준 — 화면 색상/갤러리 우선 (철회)

2026-11-09 사용자 사진 검수 후 범위를 수정했다. 아래의 50색상/19색상 검증 기록은 **이전 구현 기록**이며 현재 수집 범위가 아니다.

- `11016`: 공식 masterProductId와 variant ID는 11016이지만 내부 응답에 남은 19색상을 현재 상품 색상으로 간주할 수 없었다. 현재 색상 스와치에는 블랙(001), 핑크 레모네이드(669)만 표시된다. 수정본은 이 2색상만 수집한다.
- `10126`: 현재 화면 스와치 8색상만 수집한다. 화면에 실제 표시된 disabled/품절 스와치는 포함하되 내부에만 남은 이력 색상은 제외한다.
- `10116`은 이번 공식 검색에서 정확한 상품 링크를 확인하지 못했다. 사용자가 확인한 품번은 11016으로 정정했다.
- 펄핑크/와일드오키드(6MB)의 ALT210은 공식 imageGroups에도 들어 있었지만 리뷰를 연상시키는 착용 사진이었다. 공식 배열 소속만으로 등록용 사진에 적합하다고 판정한 것이 잘못이었다. ALT210 및 리뷰/UGC/라이프스타일 신호는 제외하며, 후보는 실제 `[data-slot=pdp-gallery]` 안에 표시된 사진으로 제한한다.
- 각 화면 색상의 실제 상세페이지를 조회해 masterProductId와 상품 링크를 확인하고, 현재 갤러리의 실제 URL과 공식 색상별 asset ID를 다시 대조한다. 고해상도 템플릿 확장과 과거 색상 복원은 제거했다.
- 실제 worker 검증: 11016 2행/exit 0 (약 19초), 10126 8행/exit 0 (약 38초). 화면 색상 필터, 표시된 품절 유지, 다른 품번 거부, 리뷰 영역/ALT210 다운로드 금지 회귀 테스트 추가.

기존 19색상/50색상 결과는 새 기준의 등록용 결과로 사용하지 않는다. Hub 재시작 후 새 작업에서 다시 수집한다.

2026-11-09, 기존 develop 작업 폴더에 추가. 커밋/푸시하지 않음.

- 입력: `10126` (전체 색상), `10126-100` 또는 `10126_100` (화이트).
- 설치된 Google Chrome과 기존 Hub의 Playwright를 사용한다. 일반 HTTP 상품 요청은 403을 반환해 Chrome으로 공식 검색/상품 페이지를 조회한다.
- 공식 RSC `product.masterProductId`로 품번 확인, `variationAttributes.color` 및 `imageGroups.variationAttributes.color`로 색상/이미지 연결을 대조한다.
- 사이즈 옵션은 색상별 `variants.variationValues.size`를 공식 표시명으로 변환하며 품절도 포함한다.
- 판매가 `variants.price`, 정상가 `variants.retailPrice`를 독립 선택한다. 정상가 누락/0/잘못된 형식/상이한 사이즈별 가격은 빈칸이다.
- 고시는 상세설명에 대응하는 겉감/안감/수입자 텍스트를 출력한다. 사이즈표는 ‘사이즈 표 보기’의 실제 표를 재구성한다. 없는 고시/사이즈표는 생략하고, 로딩/파싱 실패는 부재로 감추지 않는다.
- 화면에서 확인한 공식 900px 이미지 변환 경로와 RSC의 색상별 원본 asset ID를 연결한다. 각 주소는 독립적인 공개 GET/실제 이미지 검사 후에만 채택한다. 품절 색상에서 화면이 기본색으로 돌아가도 그 기본색 사진을 재사용하지 않는다. URL의 확장자를 임의로 바꾸지 않는다.
- 공개 이미지 GET, 실제 파일 형식/픽셀/용량, 갤러리 역할 및 제외 신호 검사 후 대표 1장/추가 5슬롯을 만든다. 내용 해시는 중복 제거에만 쓴다. 완전한 시각 인식이나 WING 등록 승인을 보장하지 않는다.
- Chrome 프로필은 각 작업의 `ctx.output_dir/crocs-browser` 아래에만 생성한다.
- 전 색상의 variants/imageGroups가 들어 있는 master 응답을 한 번 확인하고 재사용한다. 50색상을 수집하려고 상품 페이지를 50번 다시 열지 않는다. 상품 링크는 실제 조회·품번 확인에 사용한 master 상세 URL이다.
- 공개 이미지 확인은 최대 4개 요청을 병렬 처리하며 색상별 진행 단계를 표시한다. 이미지 바이트 캐시는 색상 완료 후 해제한다.

## 초기 전체 수집 오류 수정

사용자 작업 로그에서 50색상 중 품절 색상을 조회하면 화면 갤러리가 기본색으로 돌아가 작은 `t_standard` 이미지로 폴백하고, 이미지가 전부 규격 미달로 탈락한 것을 확인했다. 이미지의 순차 확인과 색상별 상세 재조회도 지연을 키웠다. 초기 50색상 테스트는 이미지 미선택 상태였으므로 이 문제를 놓쳤다.

수정 후 품절 `10126-014`에서 공식 900×900 사진 6장과 사이즈·가격·고시·사이즈표·SDK Excel 저장을 실제 확인했다. 다른 색상 DOM에서도 해당 품절 색상 asset ID를 유지하는 회귀 테스트와 master 응답을 한 번만 읽는 회귀 테스트를 추가했다.

최종 수정본의 실제 `10126` 전체 선택 수집: **50색상/50행 성공**, 전 행 대표이미지·추가 5슬롯·사이즈표 있음. SDK 엑셀 저장 후 Hub 최종 검수 함수에서도 **50행 모두 normal, 확인 필요 0행**을 확인했다. 로컬 전체 검증은 약 3분 소요됐으며 사이트 응답에 따라 달라진다. 검증 엑셀: `C:\Users\0928a\AppData\Local\Temp\crocs-verify-ygo_5hp0\result.xlsx`.

## Hub worker 이벤트 전송 수정

후속 실제 작업의 `Extra data: line 1 column 44 (char 43)` 오류는 병렬 공개 이미지 요청에서 worker의 네트워크 훅이 stage 이벤트를 동시에 출력해 JSON 두 개가 한 줄에 붙는 문제였다. 직접 crawl/SDK 테스트에는 작업 관리자의 stdout 파싱이 없어 놓쳤다.

`app/worker.py`의 emit을 공통 lock 안에서 JSON 이벤트와 줄바꿈을 한 번에 쓰도록 수정했다. `tests/test_worker_events.py`는 실제 worker subprocess에 12개 thread의 120개 이벤트를 보내며 stdout을 9글자씩 강제로 분할해도 모든 이벤트가 정상 JSON 한 줄로 유지되는지 검사한다.

실제 Hub worker subprocess + 전체 선택 옵션으로 `10126` 재검증: exit 0, 50행, JSON 이벤트 700개 정상 수신, 약 62초. 이 수정은 브랜드 코드 외에 worker 실행부에도 있으므로 Hub를 재시작하고 새 작업을 만들어야 한다.

동일 경로 `11016`: exit 0, 19색상/19행, JSON 이벤트 258개 정상 수신, 약 44초. `10126`의 실제 worker 결과에 Hub 최종 검수 적용 시 50행 모두 normal, 확인 필요 0행. worker 이벤트 테스트 1개 및 크록스 회귀 테스트 5개 통과.

실제 사이트에서 다른 기본 품번, 고시/표가 원래 없는 상품, WING 업로드는 아직 검증하지 않았다. 기존 실행 창과 기존 작업은 로컬 배포 스냅샷을 사용하므로 종료 후 이 저장소의 Windows 실행 파일로 다시 실행하고 **새 작업**을 만든다. 기존 작업의 이어하기는 저장된 예전 코드를 재사용할 수 있다.
