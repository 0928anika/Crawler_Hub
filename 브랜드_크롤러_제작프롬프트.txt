
[판매가·정상가 표준 선택 수집 규칙 — 2026-11-09]
- 기존 price 필드의 화면·엑셀 이름은 "판매가"다. price 키는 호환성을 위해 유지한다. 별도 선택 필드 regular_price의 이름은 "정상가"다.
- output_headers에는 "판매가", "정상가"를 각각 선언한다. capabilities.regular_price에는 supported/status/reason과 확인한 공식 필드·선택자 근거를 작성한다.
- 독립 정상가·소비자가·최초출시가를 공식 원문에서 확인한 경우에만 regular_price에 KRW 숫자를 넣는다. 판매가/회원가/쿠폰가를 대체값으로 사용하거나 할인율로 역산하지 않는다.
- 정상가 전용 요청과 파싱은 ctx.enabled('regular_price')가 true일 때만 수행한다. 판매가와 정상가는 서로 독립적으로 선택·생략할 수 있어야 한다.
- 정상가 출처 자체가 확인되지 않으면 supported=false, status=unsupported와 정확한 reason을 작성한다. 실행 전 "수집 불가"로 표시되어야 한다.
- 정상가 지원 브랜드라도 일부 품번의 값이 없거나 0·불명확·형식변경·정상가 전용 통신 실패이면 regular_price=None, 빈 셀과 안내 로그만 남기고 나머지 항목 수집을 계속한다.
- 정상가 단독 누락으로 ctx.fail_item, 필수 누락 오류, 색상 실패나 품번 실패를 발생시키지 않는다. 필수 상품명·색상·상품 링크 확인 실패와 일반 수집 오류는 기존 실패 계약을 유지한다.
- 정가가 판매가와 같을 수는 있지만 각각 공식 필드가 확인돼야 한다. 정상가가 없다는 이유로 판매가를 복사하지 않는다.
- 수동 매핑·이미지 저장형에서 여러 상품 링크의 공통 정상가를 확정할 수 없으면 빈칸이다. 사진 색상으로 정상가를 추측하거나 서로 다른 정상가 중 임의의 하나를 공통 값으로 선택하지 않는다.
- record['정상가'] 같은 무조건 추가 열 방식은 사용하지 않는다. 표준 키 record['regular_price']를 선택된 경우에만 추가한다.
- 테스트: 판매가만/정상가만/둘 다/둘 다 미선택, 정상가 누락·0·잘못된 형식·전용 요청 실패, 정상가 미지원, 서로 다른 공통 정상가를 검증한다. 정상가 누락 상품도 다른 필수 항목이 정상이면 수집 성공이어야 한다.

예시:
if ctx.enabled('regular_price'):
    ctx.checkpoint()
    try:
        # 공식 독립 정상가 출처에서만 수집. 실제 출처를 확인한 구현으로 교체한다.
        record['regular_price'] = fetch_official_regular_price()
    except Exception as exc:
        record['regular_price'] = None
        ctx.log('정상가 확인 불가: ' + str(exc) + ' / 나머지 수집 계속', 'WARNING')
    ctx.checkpoint()

너는 Python 크롤러 개발자다. 아래 명세만으로 로컬 통합 크롤러 Crawler Hub에 붙여 넣을 브랜드 크롤러를 완성해라. 사용자는 프로그래밍 초보자다. 저장소 접근 없이도 이 계약을 지켜야 한다.

브랜드명: 여기에 입력
크롤링 소스 표시명: 예: 공식 홈페이지 / 네이버 브랜드스토어 / 네이버 NC_YS
수집 대상 사이트 URL: 여기에 입력 (공식몰 또는 사용자가 지정한 스토어)

분류: 예: 여성복 / 스포츠 / 아동복
검증할 실제 기본 품번: 여기에 입력
가능하면 색상이 여러 개 있는 상품 URL 및 품절 상품 URL: 여기에 입력

[먼저 조사할 것]
공식 사이트의 실제 검색·상품 페이지·공개 JSON/API를 확인하고 검색 입력 형식, 색상코드 유무, 색상별 이미지 연결, 품절 옵션, 별도 사이즈가이드와 상품정보고시 위치를 조사해라. 요청 URL·선택자·응답 키를 상상해서 작성하지 마라. 직접 웹에 접근할 수 없다면 필요한 상품 HTML·응답 JSON·샘플 URL을 먼저 요청해라. 접근·매핑이 확인되지 않았는데 완성된 크롤러라고 주장하지 마라. 이 프롬프트는 색상별 이미지 매핑이 가능한 사이트 전용이다. 수동 매핑이 필요하면 그 사실을 알려라. 단, 색상-이미지 매핑 확인과 사진 내용의 수동 검증을 혼동하지 마라. 모든 사진을 사람이 확인해야만 수집하는 구조로 만들지 않는다.

[최종 출력은 반드시 두 부분으로 분리]
A. 브랜드 정의: 완전한 JSON 코드블록 하나.
B. 크롤러 Python 코드: 첫 줄이 PORTAL_API_VERSION = 1인 완전한 Python 코드블록 하나.
실제 구현을 요구한 최종 코드에는 TODO, pass, NotImplementedError, 가짜 응답, 샘플 데이터, 생략부호를 남기지 마라. 구현 근거가 부족하면 먼저 필요한 자료를 물어라. Level 2나 execution_level: 2를 사용하지 마라.
각 부분 앞에 붙여넣을 위치를 한 문장으로 안내해라. JSON은 첫 {부터 마지막 }까지 관리자 '브랜드 정의'에, Python은 첫 PORTAL_API_VERSION = 1부터 마지막 줄까지 관리자 '크롤러 Python 코드'에 넣는다. ```json, ```python, 마지막 ``` 및 A/B 제목은 입력란에 붙이지 않는다. 브랜드 ID/브랜드명/분류/크롤링 소스는 관리자 위쪽 네 입력란에도 동일하게 넣는다. 브랜드명에는 소스를 붙이지 말고 순수 브랜드명만 넣는다. 화면에서 자동으로 브랜드명 (크롤링 소스)로 표시한다. 소스별로 ID와 Python 파일을 분리하며, 이름이 같다는 이유로 기존 다른 소스의 브랜드를 덮어쓰지 않는다. 새 브랜드 저장 시 공유 루트의 brands/<브랜드ID>.py에 코드가 저장된다. 브랜드 정의의 script에는 폴더 없이 <브랜드ID>.py만 쓴다. 기존 브랜드 수정은 관리자 목록에서 해당 브랜드를 먼저 선택한다. Crawler Hub이 기존 script 경로를 자동 유지하므로 사용자가 경로를 직접 고치거나 파일을 이동할 필요가 없다. 브랜드 정의의 script가 일반 템플릿 경로여도 기존 등록 경로에 저장한다.

[B. Python 실행 계약]
첫 줄 PORTAL_API_VERSION = 1, 진입점 def crawl(ctx): 이다. Crawler Hub은 입력 엑셀의 현재 품번 한 행마다 별도 프로세스로 호출한다. ctx.product_code는 현재 품번 문자열, ctx.item은 현재 입력 행 dict다. 전체 엑셀을 다시 읽거나 전체 품번 반복을 하지 마라. input()·별도 GUI·자체 Excel 저장·별도 서버 실행은 금지한다. Crawler Hub이 Excel/로그/체크포인트/재시도/이어하기를 관리한다. 결과·캐시·임시파일은 ctx.output_dir 아래만 저장하고 소스/OneDrive/SharePoint 폴더에는 쓰지 마라. 이 폴더는 Crawler Hub이 각 사용자 로컬 저장소로 지정한다. 판매자 인증정보·쿠키·토큰은 코드나 JSON에 넣지 마라.

사용 가능한 API:
- ctx.enabled(field) -> bool: 필드 선택 여부.
- ctx.collect(field, loader) -> loader 결과 또는 미선택 시 None. loader는 인자 없는 함수다. lambda: fetch()처럼 전달하며 fetch()를 먼저 실행하지 않는다.
- ctx.stage("설명"): 진행단계 표시 및 체크포인트.
- ctx.checkpoint(): 일시정지 확인. 네트워크 요청 전후, 색상·이미지 반복마다 호출한다.
- ctx.log("설명", "INFO"/"SUCCESS"/"WARNING"/"ERROR"): URL과 이미지 탈락 사유 등 기록.
- ctx.emit_result(record): 색상 하나의 완성 결과를 즉시 보내 저장·미리보기 반영. 반환값으로 결과 전달하지 않는다. 같은 색상의 사진 한 장마다 호출하지 않는다.
- ctx.fail_item(message): 명시적인 수집 실패를 기록한다. 즉시 예외를 던지지 않으므로 다른 색상의 완료 결과를 계속 전달할 수 있다. Crawler Hub이 crawl 종료 후 실패를 확정하며, 크롤러도 반복 종료 시 모은 오류로 예외를 발생시켜라. ERROR 로그만으로 이 기능을 대신하지 마라.
- ctx.output_dir: pathlib.Path 로컬 작업 출력 폴더. ctx.input_path는 전체 입력 경로지만 직접 반복하지 않는다.

record 영문 키:
필수 product_code, product_name, color, product_url.
보조 color_name, color_code. JSON output_headers에 색상명/색상코드가 있어야 각각 열로 나온다.
선택 size, price(판매가), regular_price(정상가), category, main_image, additional_images, detail_page.
main_image는 URL 문자열 하나, additional_images는 URL 5개를 쉼표로 연결한 한 줄 문자열, detail_page는 통합 HTML 문자열이다. size도 사이즈를 쉼표로 연결한 한 줄 문자열, 가격은 숫자, 카테고리는 문자열이다. size와 additional_images를 emit_result에 리스트/튜플로 전달하지 마라. 현재 SDK는 리스트/튜플을 줄바꿈으로 연결하므로 반드시 브랜드 코드에서 먼저 쉼표 문자열로 변환한다. 추가 수집 값은 의미 있는 추가 열 이름으로 emit_result의 record에 넣는다. 내부 진행 상태는 결과 열이 아니라 로그로 남긴다. 실제 필수 정보가 없으면 정상 결과를 조작하지 말고 명확한 오류를 올려 재시도 대상으로 남긴다. 빈 검색 결과를 정상 완료로 처리하지 마라.

기본 라이브러리 외 설치된 패키지: beautifulsoup4, openpyxl, Pillow, playwright. HTTP는 urllib.request를 사용할 수 있다. requests 등 추가 패키지가 있다고 가정하지 마라. Playwright 브라우저 설치가 필요한 경우 사용자에게 별도 설치 필요를 명시하고, 가능하면 공개 HTML/JSON으로 구현한다. 차단·CAPTCHA를 무한 반복하거나 우회하지 말고 제한된 재시도 후 원인을 표시한다. HTTP timeout·최대 재시도·최대 응답 크기를 둔다.

[상품 소속 확인 — 상품명 브랜드명 검사 금지]
사용자가 제공한 브랜드 몰·스토어 링크를 수집 범위의 기준으로 삼는다. 상품명에 브랜드 이름이 없어도 정상 상품이므로 수집해야 한다. 예를 들어 행텐틴즈 몰의 상품명이 "주니어 코튼 티셔츠 14590-010-801-41"이어도 "행텐틴즈"가 없다는 이유로 제외하거나 실패시키면 안 된다.
상품명·페이지 제목·색상 옵션에 브랜드명 또는 브랜드 별칭이 포함되어야 통과하는 조건, 정규식, assert, allowlist를 만들지 마라. 브랜드명이 있다는 사실만으로 품번 일치를 대신하지도 마라. 상품명에서 브랜드명을 제거하는 규칙은 실제로 포함된 경우에만 적용하는 출력 정리 규칙이며, 브랜드명 존재를 필수 조건으로 삼는 검사가 아니다.
상품 확인에는 사용자가 지정한 몰/스토어 범위, 실제 검색 결과와 상품 페이지의 공식 상품 ID·자체상품코드·품번 등 사이트에서 확인되는 식별 정보를 사용한다. 공식 품번이 별도 필드에 있다면 상품명에 품번이 없더라도 그 필드로 대조한다. 정확한 품번을 확인할 수 없는 경우에는 그 식별 근거 부족을 구체적으로 기록하고, 브랜드명이 없다는 오류로 바꾸지 않는다. 공통 CDN·공식 상품 링크 이동은 실제 사이트 연결 근거를 확인하여 처리한다.
검증에는 반드시 같은 브랜드 몰에서 브랜드명이 포함된 상품명과 포함되지 않은 상품명을 모두 넣고, 두 경우 모두 동일한 품번·색상 확인 기준으로 통과하는지 확인한다. 다른 품번이거나 지정 몰/스토어와 무관한 상품은 별도로 구분한다. 특정 브랜드 이름을 하드코딩한 상품명 필터를 생성하지 마라.

[반드시 지킬 수집 규칙]
1. 기본 품번 입력은 공식 사이트의 해당 품번 모든 색상을 수집한다. 판매 중인 첫 색상만 가져오지 않는다. 색상마다 emit_result를 호출한다. 수집 가능한 품절 상품·품절 색상·품절 사이즈도 생략하지 않는다. 재고가 0이라는 이유로 continue하지 않는다.
2. 실제 공식 색상코드가 있는 사이트는 기본품번_색상코드를 지원한다. 공식 표기가 기본품번-색상코드인 브랜드는 하이픈과 언더바 둘 다 허용한다. 특정 색상을 입력하면 해당 색상만 수집한다. 공식 색상코드가 없는 사이트에는 이 기능을 제공하지 않는다. 품번 자체의 하이픈을 무작정 색상 구분자로 나누지 말고 공식 조회 결과와 대조한다. 색상명에서 코드를 추측하거나 가짜 번호를 만들지 않는다.
3. 상품명은 브랜드명과 공식 품번을 제외한 실제 상품명만 남긴다. 예: '언더아머 남성용 티셔츠 12345' -> '남성용 티셔츠'. 한국어·영문 브랜드 별칭과 공식 품번 토큰을 확인하여 제거하며, 품번 일부와 우연히 겹치는 상품명 문자열을 무작정 replace하지 않는다.
4. 색상명/색상코드를 분리한다. 공식 옵션명 '39 Ivory'에서 실제 39가 색상코드라는 근거가 있으면 color_name=Ivory, color_code=39. 별도 코드 IV, 이름 아이보리면 각각 그대로. color에는 이름이 있으면 이름, 없으면 실제 코드만 넣는다. 한쪽만 알면 그쪽만 채우고 다른 쪽은 빈 값. 원본 옵션 문자열의 숫자를 근거 없이 색상코드로 단정하지 않는다.
5. 필수 품번/상품명/색상/상품 링크는 항상 수집. 선택 사이즈/판매가/정상가/카테고리/대표이미지/추가이미지/상세페이지는 ctx.enabled 안에서만 해당 추가 요청·파싱·이미지 다운로드·HTML 생성을 실행한다. 결과 저장할 때만 열을 지우는 방식은 금지다. 공통 기본 응답의 필수 데이터는 공유할 수 있다. 대표 또는 추가 중 하나라도 선택했으면 이미지 검사는 공유할 수 있지만 둘 다 미선택이면 갤러리 전용 작업을 하지 않는다. 상세페이지 미선택이면 별도 상세/고시/사이즈가이드 전용 요청도 하지 않는다. 단, 상세페이지가 선택됐다면 사이즈 열 미선택이어도 상세에 필요한 사이즈표는 수집한다. 사이즈 옵션과 사이즈표는 다른 자료다.
6. 대표이미지 1개, 추가이미지 5슬롯. 판별 가능한 대표와 동일한 컷은 추가 후보에서 제외한다. 추가 후보가 부족하면 통과한 추가 컷을 반복하여 5슬롯을 채운다. 유효한 컷이 대표 1장뿐이면 그 컷을 추가에도 재사용하되 WARNING에 명시한다. URL 별칭이 같은 이미지인지 확인 가능하면 실제 내용 해시·공식 이미지 ID로 비교한다. 동일 여부를 확인할 수 없으면 중복 허용이다. URL을 발명하거나 탈락 이미지를 패딩용으로 다시 넣으면 안 된다. 통과 이미지가 0장이면 빈 이미지와 검수 경고를 남기고 상품의 필수 정보는 보존한다.
7. 상세페이지 HTML에는 상품 이미지+상품정보고시+사이즈표 세 종류만 넣는다. 별도의 소재 및 관리 방법·케어 아이콘·배송·교환·반품 안내·리뷰·추천상품·혜택·사이트 공통 안내는 제외하고 해당 자료 전용 요청도 하지 않는다. 상품정보고시 안의 소재/혼용률 같은 실제 고시 항목은 유지한다. 별도 '사이즈 가이드', '세부정보', '상품정보' 탭에서는 상품고시와 사이즈표에 해당하는 내용만 골라 가져온다. 탭 전체 HTML을 복사하지 않는다. 원문 글자/단위/표를 보존한다. 없는 고시·사이즈표는 만들어내지 말고 WARNING 후 없는 상태로 완성한다. 상세 이미지가 아니더라도 HTML 표가 있으면 포함한다. script/iframe/이벤트속성을 제거하고 상대 이미지 URL을 절대 URL로 바꾸며 텍스트는 escape한다. 상세용 사진/표는 main_image/additional_images에 섞지 않는다. 측정사진·사이즈표는 상세에 사용 가능하다.
8. 색상과 이미지의 공식 연결이 증명된 경우만 이 자동 크롤러 방식으로 구현한다. 배열 순서, 파일명 색감 추측, 첫 갤러리의 전 색상 재사용으로 매핑을 꾸미지 마라. 매핑 불가면 별도 수동 매핑 유형이 필요하다고 알려라.

[WING 이미지 사전 필터 — 매우 중요]
대상은 WING 웹/엑셀 상품등록이다. 2026-11-04 확인한 공식 안내 https://marketplace.coupang.com/mba/listing 에는 최소 500px 이상, 권장 1000x1000, 10MB 이하, JPG/PNG가 안내되어 있다. 그러나 안내에 WebP가 없다는 사실만으로 모든 WING 등록 경로에서 WebP가 차단된다고 단정하지 마라. 사용자는 실제 사용하는 등록 경로에서 WebP 등록 성공을 확인했다. 이 프로젝트는 보수적으로 가로·세로 모두 500px 이상, 실제 파일 10,000,000바이트 이하로 검사한다. 다른 등록 방식의 API 기준을 섞지 마라. 구현 시 해당 카테고리·등록 방식의 최신 공식 안내도 확인하고 검사 정책/근거/확인일을 코드 상수에 기록한다. 상품별 인증·고시 등 전체 판매 승인까지 보장한다고 말하지 않는다.

대표·추가 갤러리에 대해서:
- 확장자만 믿지 말고 제한된 크기로 다운로드한 실제 바이트를 Pillow로 해독·verify하여 형식/크기/픽셀을 확인한다. HTML 오류 페이지·손상 파일·작은 썸네일·용량 초과는 제외하고 사유를 로그에 남긴다. 현재 사용자 등록 환경에서는 정상 정지 WebP도 후보로 허용하며 WEBP라는 이유만으로 탈락시키지 않는다. 애니메이션 여부와 실제 형식을 따로 기록하고 애니메이션 형식의 호환성을 정지 이미지와 혼동하지 않는다. 공식 고해상도 원본이 확인되면 그 URL을 사용해 다시 검사한다.
- 여러 장이 이어진 세로/가로 통짜, 콜라주, 여러 컷 합성, 배너, 로고 단독, 색상 스와치, 상품고시, 사이즈표, 사이즈 측정사진·측정선 도식은 대표·추가에서 제외한다. 형식/픽셀이 맞아도 제외한다. 잘라서 만든 이미지나 임의 업스케일, 확장자만 변경한 URL로 기준을 속이지 않는다.
- 비율은 보조 신호다. 기본 max(가로,세로)/min(가로,세로)>1.8은 프로젝트의 보수적 통짜/배너 의심 규칙으로 제외한다. 이것을 쿠팡 공식 비율 제한이라고 주장하지 마라. 공식 안내는 정사각형이 아닌 이미지를 자동 리사이즈할 수 있다고 한다. 1.8 이하의 정사각형 콜라주도 있으므로 비율만 통과했다고 개별 컷이라고 판단하지 않는다.
- 일반 상품컷은 다음 조건을 모두 검사하여 자동 채택한다: (1) 공식 상품/색상별 상품 갤러리에서 나온 URL이고 해당 색상 매핑이 확인됨 (2) 공개 접근·실제 파일 규격 통과 (3) 사이트 구조상 상품 사진 역할의 영역/응답 필드에서 추출됨 (4) 통짜 의심 비율과 사이즈표·측정사진·고시·배너·콜라주 등의 구체적인 제외 신호가 없음. “이 사진을 사람이 사전에 확인하지 않았다”는 이유만으로 제외하지 않는다.
- 색상 매핑 근거는 공식 상품 ID/색상 ID/갤러리 연결로 기록한다. 개별 컷 판정 근거는 실제 적용한 DOM/응답 필드 역할, 가로·세로·비율, alt/주변 제목/파일 경로 등 제외 신호 검사 결과로 기록한다. 공식 갤러리라는 한 문장만으로 통과시키거나 검사 없이 True를 넣지는 않는다. 이 판정은 규칙 기반이며 완벽한 시각 인식이라고 주장하지 않는다.
- 파일명/alt/주변 제목의 size/guide/chart/measurement/사이즈/실측/측정/고시 등의 신호와 통짜·배너 비율을 함께 사용한다. 공식 상품 갤러리의 일반적인 이미지 순번 _01, _02 등은 부정 신호가 아니다. 일반 촬영컷·모델 착용컷·상품 디테일의 개별 사진은 허용한다. 이미지 안의 문구나 모양까지 자동으로 완벽히 구분할 수 있다고 주장하지 않는다.
- 사진마다 사전 등록된 SHA256 해시, 특정 품번·색상·이미지 URL 허용목록과 일치해야만 통과하는 구현을 금지한다. 샘플 상품은 파서 검증용이지 운영 허용목록이 아니다. 해시는 같은 사진의 중복 제거와 캐시 용도로만 사용할 수 있다. 다른 품번이나 CDN 재인코딩 때문에 정상 사진 전부가 탈락하는 구조를 만들지 마라.
- UNKNOWN 자동 제외는 상품/색상 매핑이 불명확하거나, 이미지 역할이 상품 사진과 사이즈자료 등으로 혼재해 분리되지 않거나, 실제 접근/파일 검증이 불가능한 경우처럼 구체적인 위험이 있을 때 사용한다. 정상 갤러리 사진에 “수동 내용 검증 없음”만을 이유로 UNKNOWN을 부여하지 않는다. 분류가 실제로 모호한 사진은 제외 사유를 남기고 다른 정상 컷을 사용한다.
- 알려진 통짜·콜라주·측정사진이나 규격 미달 사진을 추가 5장 맞추려고 되살리지 않는다. 대표가 탈락하면 다음 유효한 개별 컷을 고른다. 코드상 적용한 각 조건과 탈락 사유를 기록하며, 일반 사진까지 전부 탈락했으면 실제 파일 형식·파서·조건 오류부터 점검한다.
- 상세페이지에는 위 갤러리용 비율/측정사진 제외 규칙을 그대로 적용하지 않는다. 상세의 사이즈표·고시·측정사진과 필요한 상세 이미지는 유지한다.

clean_product_name(name, brand_aliases:list, product_codes:list) -> str
resolve_input(value, official_variants:list[(base_code,color_code)], has_color_codes=False, hyphen_alias=False) -> (base_code, requested_color_or_None). 실제 조회한 공식 변형 목록을 넣는다.
validate_gallery_image(data:bytes, *, role, mapping_verified, single_shot_verified, evidence='', mapping_evidence='', content_evidence='', max_aspect=1.8, min_side=500, max_bytes=10000000) -> dict(passed, status, reasons, width, height, evidence, mapping_evidence, content_evidence). role='product_shot'와 근거 문자열이 필요하며 실제 바이트 검사는 이 함수가 한다. 신규 코드의 single_shot_verified는 아래 일반 상품컷 채택 규칙을 실제로 검사해 통과했다는 의미로 사용하며, 사람이 해당 사진을 사전 승인했다는 뜻으로 사용하지 않는다. 내용/색상 근거는 브랜드 어댑터가 직접 검증하여 전달한다. 신규 코드에서는 mapping_evidence와 content_evidence를 별도로 전달한다. evidence는 구버전 호환용이다. 공식 갤러리 소속만 단독 근거로 쓰지 말고 이미지 역할·실제 크기/비율·부정 신호 검사 결과를 함께 기록한다. 매번 수동 확인한 해시를 요구하지 않는다.
gallery_slots(candidates) -> (main_url_or_None, extra_urls, warning). candidates는 [{'url':공식URL,'validation':검사결과}, ...]이며 passed=True 후보만 사용한다. 대표 1개와 추가 5슬롯을 만든다. 대표와 다른 컷의 실제 내용 비교가 가능한 경우 호출 전에 같은 컷을 제거한다.

[실패·재실행 계약]
- 일부 색상의 필수 정보 수집에 실패했다면 가능한 다른 색상 결과는 emit_result로 전달하되, ctx.fail_item으로 실패를 기록하고 마지막에 예외를 발생시켜 입력 품번을 실패로 남긴다. 오류 로그만 남기고 정상 종료하지 않는다.
- 예: failures=[]를 만들고 색상별 try/except Exception에서 ctx.fail_item과 failures.append를 실행한다. 다른 색상을 계속 처리한 뒤 failures가 있으면 RuntimeError를 발생시킨다. 필수 정보 실패를 빈 정상 행으로 메우지 않는다. KeyboardInterrupt/SystemExit 등을 삼키는 bare except는 금지한다.
- 선택된 항목의 조회가 재시도 후에도 통신 오류로 끝나 수집을 완결하지 못하면 실패로 전달한다. 원래 없는 자료와 구분한다. 사이즈표·고시의 원래 부재, 이미지 후보 필터 탈락·내용 UNKNOWN은 WARNING이며 그 이유만으로 상품 전체를 실패시키지 않는다. 이미지 0장도 빈 이미지와 검수 경고를 남긴다. 단, 0장을 당연한 정상 결과로 간주하지 말고 허용목록 하드코딩·실제 형식 판정·공개 접근·영역 추출 오류 때문에 정상 갤러리를 전부 버린 것은 아닌지 검증한다.
- 재실행 단위는 입력 엑셀 한 행이다. 색상 10개 중 7개를 모으고 중단했다면 그 품번 전체를 다시 수집한다. 완료된 다른 입력 행은 건너뛴다. Crawler Hub이 해당 행의 이전 부분 결과를 교체하므로 중복 append, 자체 완료 목록, 별도 색상 체크포인트를 만들지 않는다.
- 같은 입력 엑셀의 중복 품번 행은 별개의 입력 행이다. 브랜드 코드가 임의로 전체 입력을 중복 제거하거나 다른 행을 건너뛰지 않는다.

[사이즈 가이드 출력 순서 — 그림 먼저, 표 나중]
상세페이지의 사이즈 가이드는 반드시 ‘사이즈 측정 그림(치수 위치 도식·측정 사진) → 해당 사이즈표 → 표 해석에 필요한 단위·짧은 주석’ 순서로 출력한다. 원본 사이트의 DOM이나 응답에서 표가 먼저 나와도, 최종 HTML에서는 관련 그림을 먼저 배치하고 그 바로 아래에 표를 배치한다. 사이즈표를 먼저 넣은 뒤 측정 그림을 뒤에 붙이지 마라. 여러 종류의 표와 그림이 있으면 서로 대응하는 그림·표를 한 묶음으로 유지하며 각 묶음에서 그림이 먼저 나오게 한다. 그림이 없으면 표만, 표가 없으면 실제 존재하는 그림만 사용하고 누락 자료를 만들지 않는다. 이 순서는 자동 매핑 및 수동 매핑의 공통 상세 HTML 모두에 적용한다. 최종 HTML의 실제 요소 순서가 그림 다음 표인지 검증한다.

[상세페이지 수집 범위: 세 종류만 허용]
- 최종 상세 HTML의 내용은 (1) 해당 상품/색상 상품이미지 (2) 실제 상품정보고시 표 (3) 실제 사이즈표와 그 표 해석에 필요한 치수 그림·단위·짧은 주석뿐이다.
- 별도의 '소재 및 관리 방법', '세탁 및 취급 방법', 케어 아이콘, 배송/교환/반품/환불 안내, 판매자 공통 안내, 리뷰, 추천상품, 쿠폰/혜택, 장바구니/구매 UI는 수집·출력하지 않는다. 단, 상품정보고시의 소재·혼용률·취급주의 등 공식 항목은 고시 표의 값이므로 해당 행을 임의로 삭제하지 않는다.
- 공식 페이지의 상품이미지·상품고시·사이즈표를 정확히 선택하는 허용목록 방식으로 구현한다. 모든 상세 탭/아코디언/카테고리 영역을 통째로 순회한 뒤 배송 제목 하나만 제외하는 방식은 금지한다. 제외 섹션을 다운로드·이미지 검사한 후 버리는 방식도 금지한다.
- 제외 섹션의 care_*.gif 등은 상세 결과에 필요 없으므로 접근·해독·404 여부를 검사하지 않는다. 사이트 공통 이미지가 깨진다는 이유로 정상 상품 수집을 실패시키거나 검수 경고를 만들지 않는다.
- 같은 이름의 '소재'가 있다는 이유로 상품정보고시 내부의 행까지 통째로 삭제하지 않는다. 섹션 단위와 고시 항목 단위를 구분한다.

[상품정보고시: 실제 항목·값을 추출해서 2열 표로 재구성]
- 고시 제목의 존재 여부만 검사하거나 해당 부모 영역의 HTML을 그대로 복사하는 것으로 구현을 끝내지 마라. 원본이 dl/dt/dd, div/span, 기존 table, 공개 JSON 중 어떤 구조든 실제 '항목명-값' 쌍을 먼저 추출한다.
- 최종 HTML은 <h3>상품정보고시</h3><table><tbody><tr><th>항목명</th><td>실제 값</td></tr>...</tbody></table> 형태의 실제 2열 표로 새로 만든다. dl/dt/dd를 그대로 출력하거나 모든 글자를 한 문단으로 이어 붙인 결과는 불합격이다.
- 원문 항목 순서, 실제 값, 단위, 제조년월, 제조사/원산지, 고객센터 등의 고시 내용을 보존한다. 텍스트는 html.escape로 처리하고 숫자·연도·원산지·소재를 샘플 값이나 현재 연도로 임의 대체하지 않는다. 원문에 실제로 적힌 '상세페이지 참조'는 보존할 수 있지만, 값을 못 찾았다고 임의로 그 문구를 채우지 않는다.
- 비어 있지 않은 원본 값이 출력에서 빈 셀로 바뀌지 않도록 한다. td/dd 안의 중첩 p/span/br 텍스트도 읽고, 라벨과 값을 같은 행에 대응시킨다. 웹페이지의 클래스·스타일에 의존하는 원본 조각 대신 의미 구조가 완성된 table/tr/th/td를 만든다.
- 표는 폭 100%, border-collapse, 최소 테두리·셀 여백, 항목명 배경 정도의 간결한 표현을 목표로 한다. 사이트 전체 CSS나 과도한 행별 속성은 복사하지 않는다. 단, 현재 Crawler Hub 공통 정제기는 inline style을 제거할 수 있다. 실제 최종 Excel HTML과 검수 렌더링을 확인하고, 프롬프트/브랜드 코드만으로 공통 정제기의 스타일 제거까지 해결했다고 주장하지 마라. 최우선은 고시 표 구조와 값의 보존이다.
- 사이즈표도 이미지로만 퉁치지 말고 공식 HTML 표가 있으면 표로 재구성한다. 실제 헤더·치수·단위·rowspan/colspan을 보존하고 상품고시와 구분된 제목 아래 둔다. 사이즈 측정사진은 이 사이즈표 구역에만 포함할 수 있다.
- 공식 페이지에 고시/사이즈표가 정말 없으면 해당 구역을 생략하고 실행 로그에 기록한다. 반면 원본에 값이 있는데 추출 결과가 0행이거나 값이 전부 비었다면 '공홈에 없음'이 아니라 파싱 실패다. 선택된 상세 수집 미완료로 명시하고 원인을 고쳐라. 제목만 달린 빈 표를 정상 결과로 내보내지 않는다.

[네파 구버전과 현재 구현 비교에서 확인한 회귀 — 일반 브랜드에도 적용]
- 예전 네파 크롤러는 .detail-category-box button 중 표시 텍스트가 '상품정보고시'인 버튼을 찾고, 그 부모 영역의 dl 각각에서 dt=항목명, dd=값을 읽어 table_html(rows)로 2열 표를 새로 만들었다.
- 현재 비교한 네파 구현은 detail()에서 .detail-category-box > div 등 넓은 영역을 safe_fragment()로 옮기고, 상품고시를 독립적인 항목·값 표로 재구성하지 않는다. 또한 .goods-detail-box의 텍스트만으로 고시 존재 여부를 판단하는 것은 실제 고시 섹션 위치와 맞지 않을 수 있다. 그대로 따라 하지 마라.
- 저장된 nepa_sample.html 비교에서는 고시 항목·값이 7쌍이고 구버전은 7행 표를 만들었지만, 현재 고시 조각에는 table이 0개였다. 이 샘플에서는 실제 값은 남아 있었으므로 모든 실제 상품의 빈 값 원인까지 확인됐다고 주장하지 마라. 해당 실행 상품의 원본 응답과 출력 값을 별도로 대조해야 한다.
- 네파를 작성할 때는 실제 응답에서 위 고시 섹션 구조를 다시 확인하여 항목·값을 추출한다. .detail-category-box 전체를 복사하지 말고 상품고시 섹션만 선택하며, 인접한 소재/관리·배송 구역과 care 아이콘은 제외한다.
- 네파 사이즈표는 실제 상품의 공식 pno에 대응하는 /pc/product/pop_sizeguide.asp?pno=... 등 별도 가이드 응답에서 읽는다. 상품 품번을 pno처럼 임의로 끼워 넣지 않는다. 다른 브랜드에 네파 전용 선택자나 URL을 그대로 적용하지 않는다.

[상세 HTML은 엑셀 셀 등록용으로 완성]
- 상세페이지는 Excel 시트로 등록하므로 32,767자 이하의 실제 등록용 HTML을 만들어야 한다. 별도 전체 HTML 다운로드로 대체하는 기능은 없다.
- 처음부터 불필요한 사이트 레이아웃·클래스·data 속성·스크립트·과한 스타일·주석을 가져오지 말고, 상품 사진과 실제 상품고시·사이즈표 세 종류만 간결한 HTML로 조립한다. 독립적인 소재 및 관리 방법이나 배송·교환·반품 설명은 넣지 않는다. 같은 이미지·같은 표·반복 문단은 중복 수집하지 않는다.
- Crawler Hub도 안전한 속성 정리, 주석·스크립트 제거, 중복 이미지와 동일 표/문단 정리, 불필요한 래퍼 축소를 수행한다. 이미지 URL의 쿼리·서명을 임의로 자르지 않는다.
- 내용과 구조를 유지한 정리 후에도 한도를 넘으면 등록용 상세 생성 실패다. 임의 문자열 절단으로 태그·고시·사이즈표를 훼손하거나, 다운로드 안내문을 HTML 셀 대신 넣지 않는다. 별도 파일로 받으라고 사용자에게 안내하지 않는다.
- 그 경우 상품·고시·사이즈표의 필요한 내용을 보존하면서 사이트 공통 안내 등 불필요한 자료를 수집하지 않도록 브랜드 코드를 더 정리해야 한다.
- 검수 미리보기와 Excel에는 동일한 정리 결과를 사용한다. 중간 후보 탈락·고시 아이콘 404 등 WARNING 로그가 있다는 이유만으로 정상 결과를 확인 필요로 표시하지 않는다. 최종 필수/선택 결과 누락·상세 한도 초과·품번 실패는 실제 검수 사유다.

[공개 이미지 URL 검사]
check_public_image(url, *, timeout=10, max_bytes=10000000, retries=1, checkpoint=None) 함수를 crawler_rules에서 import할 수 있다. 결과 dict의 status는 accessible / inaccessible / unknown, data는 통과 시 bytes, reasons와 warnings는 문자열 리스트, final_url은 최종 URL이다.
- 매 호출은 새 HTTP opener의 GET을 사용한다. 크롤러 세션 쿠키·Authorization·전용 Referer를 넘기지 않는다. HEAD 미지원만으로 탈락시키지 않는다.
- accessible은 현재 인증 없이 실제 이미지 응답이 확인됐다는 의미이며, 영구 접근이나 등록 승인을 보장하지 않는다. 이 결과만으로 색상 매핑이나 개별 컷 내용 판정까지 통과시키지 않는다.
- inaccessible은 401/403/404/410, HTML 로그인·오류 페이지, 이미지 해독 실패, 크기 제한 초과 등 관측된 거부다. unknown은 재시도 후에도 남은 일시적 통신 실패·서버 오류 등 확인 불가다. 둘 다 이유를 기록하고 자동 채택하지 않는다.
- 서명·만료 토큰 URL은 위험 경고를 기록한다. 안정적인 공식 원본이 실제 확인되면 우선하되 서명을 삭제하거나 URL을 임의 변조하지 않는다.
- 대표·추가 후보는 공개 접근 확인 후 받은 data를 validate_gallery_image에 전달한다. 별도의 규칙 기반 통짜·측정사진 제외 및 색상 매핑 판정을 수행한다. 정상 상품컷은 위 자동 채택 규칙을 적용한다.
- 상세 HTML의 이미지도 공개 접근을 확인한다. 다만 상세 자료에는 갤러리의 비율·측정사진 제외 규칙을 일괄 적용하지 않는다. 선택한 세 종류 안의 제외·확인 불가 URL은 실행 로그에 남기고 필요한 고시·사이즈표 값은 보존한다. 소재·관리·배송 등 제외 섹션의 이미지 URL은 검사 요청부터 하지 않는다.
- 요청 전후 및 재시도에 checkpoint=ctx.checkpoint를 전달한다. 필요하면 현재 색상 내 같은 URL의 검사 결과를 재사용하여 중복 요청을 줄인다. 이미지 관련 항목이 전부 미선택이면 검사 전용 요청도 하지 않는다.
- 공개 URL 검증은 공통 함수가 돕고, 공식 고해상도 원본 후보 선택과 색상/내용 근거는 브랜드 코드 책임이다. HTML에 로컬 이미지 경로나 data URI를 외부 이미지 URL처럼 넣지 않는다.

[가격과 사이즈 출력 기준]
- price는 일반 구매자가 별도 쿠폰·회원등급 없이 구매하는 현재 판매가다. 정가·회원가·최대혜택가를 혼동하지 않는다. 색상별 가격이면 해당 색상의 가격을 사용한다.
- 사이즈별 가격이 달라 하나의 숫자로 표현할 수 없으면 price=None과 WARNING을 남긴다. 임의 최저가를 넣지 않는다. 공식 사이트에 가격 정보가 없는 경우도 빈 값과 이유를 남기며, 통신 실패로 조회를 끝내지 못한 경우는 위 실패 계약을 따른다.
- 현재 Crawler Hub 가격 열은 국내 KRW 숫자 한 개다. 외화라면 자동 환산하거나 원화로 간주하지 말고 price=None으로 두고 확인한 통화·가격을 경고 로그로 남겨 검수하게 한다. 새로운 통화 결과 키를 임의로 추가하지 않는다.
- size는 해당 색상의 공식 옵션 사이즈 전체를 쉼표로 연결한 한 줄 문자열이다. 품절 포함, 공식 표시 순서 유지, 동일 옵션 중복만 제거한다. Free/ONE SIZE 등을 임의 숫자로 바꾸지 않는다. 실측 사이즈표와 사이즈 옵션은 별개다.
- price/size 미선택이면 해당 전용 요청·파싱은 생략한다. 상세페이지가 선택된 경우 상세용 사이즈표는 별도로 가져올 수 있다.

[실시간 표시의 실제 지원 범위]
- v0.6는 ctx.stage/ctx.log 진행 표시와 ctx.emit_result의 색상별 완성 결과 미리보기를 지원한다.
- 이미지 한 장마다 전달하는 임시 미리보기 이벤트/API는 제공하지 않는다. 존재하지 않는 ctx.emit_image, ctx.preview_image 등의 메서드를 만들거나 호출하지 않는다.
- 사진 한 장을 찾을 때마다 같은 색상의 emit_result를 반복하지 않는다. 색상별 결과 행은 한 번씩 전달하고, 다음 색상을 수집하는 동안 이전 색상 완성 결과는 화면에서 확인할 수 있다.
- 프리뷰 표시를 위해 미선택 항목을 몰래 수집하지 않는다. 상세용 사진은 상세페이지에만 넣는다.

[파일 형식 판정 및 HTML 처리 오류 예방]
- URL이 .jpg/.JPG여도 실제 응답 형식은 별도로 확인한다. 반대로 정상 JPEG를 문자열 표기 차이·판정 코드 오류 때문에 전부 탈락시키지 마라. 실제 Content-Type, Pillow format, 이미지 크기, 필요 시 파일 시그니처를 진단 로그에 기록한다. 파일 형식이 맞지 않다는 메시지만 반복해서 남기지 마라.
- JPEG/JPG 이름 차이, JPEG 계열의 부가 메타데이터가 있는 응답, CDN의 콘텐츠 협상 여부 등을 실제 바이트로 조사한다. 특정 원인을 확인하지 않고 단정하지 않는다. JPEG 호환 여부는 실제 파일과 해당 등록 기준을 확인한 뒤 처리하며, 실제 WebP를 JPG라고 거짓 표기하지 않는다. WebP는 사용자 등록 환경의 허용 형식으로 별도 검사하고, GIF 등 다른 형식이나 애니메이션까지 모두 허용된다고 확대 해석하지 않는다.
- 공식 사이트가 공개 JPEG/PNG 원본을 실제 제공하는 경우 그 URL을 우선한다. 근거 없는 확장자 교체·쿼리 조작·임의 변환 후 원본 URL 재사용으로 등록 가능하다고 속이지 않는다. 공개 JPEG/PNG URL이 없더라도 정상 정지 WebP가 사용자 등록 경로에서 사용 가능하면 WebP 원본 URL을 유지한다. WebP라는 이유만으로 빈 이미지 결과를 만들지 않는다. 호환성이 확인되지 않은 다른 형식만 별도로 경고한다.
- BeautifulSoup 정제 시 decompose/unwrap/replace_with를 여러 번 수행하는 동안 원래 트리에서 분리된 노드를 다시 조작하지 않도록 한다. 태그 이름뿐 아니라 현재 parent/트리 소속 여부를 확인한다. 상위 제거로 무효화된 하위 노드와 BeautifulSoup 루트 객체를 주의한다. 중첩된 제거 태그·wrapper·표가 있는 HTML로 재현 테스트한다.
- 'Cannot replace an element with its contents when that element is not part of a tree' 오류는 이미지 필터 사유가 아니라 HTML 트리 조작 오류다. 필터를 완화해서 숨기지 말고 해당 정제 코드를 수정한다.

[WebP 정책과 기존 공통 검사 함수의 주의점]
- 이번 사용자 환경의 대표·추가 후보 허용 형식은 실제 해독 가능한 JPEG/PNG/정지 WebP다. 이는 사용자 등록 성공 사례를 반영한 프로젝트 정책이며, 모든 WING 등록 방식이나 Open API가 WebP를 공식 보장한다는 뜻은 아니다. 대표/추가/상세, 파일 업로드/URL 등록의 차이를 구분한다.
- 업데이트된 Crawler Hub의 validate_gallery_image는 JPEG/PNG/정지 WebP를 허용한다. 공통 함수를 사용하면서 실제 바이트·용량·픽셀·비율·매핑·내용 제외 신호 검사를 유지한다. 애니메이션 이미지는 대표·추가에서 제외한다. 다른 검사를 생략하거나 passed 값을 무조건 True로 덮어쓰는 방식은 금지한다. 과거 작업에 고정된 이전 함수는 다를 수 있으므로 새 정책 검증은 서버 재시작 후 새 작업으로 한다.
- check_public_image의 data/format을 활용하되 실제 파일을 검증하고, URL 확장자와 실제 형식이 달라도 그 자체를 실패로 취급하지 않는다. .jpg 주소가 WebP 응답을 줄 수 있으며 원본 URL을 임의로 .webp/.jpg로 바꾸지 않는다.
- WebP의 등록 호환성은 사용자가 사용하는 경로 기준으로 판단한다. 자동 등록 실패가 실제 관측되면 그 경로와 응답을 기록하여 별도 대응한다. 크롤러가 실제 등록 테스트를 하지 않았다면 모든 형식이 등록 검증됐다고 주장하지 않는다.

[엑셀 복사·붙여넣기용 구분 형식 — 반드시 준수]
- 사이즈 최종 셀 예: 065,070,075
- 추가이미지 최종 셀 예: https://example.com/1.jpg,https://example.com/2.jpg,https://example.com/3.jpg,https://example.com/4.jpg,https://example.com/5.jpg
- 구분자는 쉼표(,) 하나이며 실제 줄바꿈, 세미콜론, 파이프, 대괄호, 셀 값을 감싸는 불필요한 따옴표를 넣지 않는다. 값 안에 \n 문자열을 넣는 것도 금지한다. 사이즈 앞자리 0을 보존하고 정수로 변환하지 않는다.
- 내부 수집·검사에는 리스트를 써도 되지만 ctx.emit_result를 호출하기 전에 문자열로 바꾼다. 예: result['size'] = ','.join(str(v).strip() for v in sizes if str(v).strip()); result['additional_images'] = ','.join(extra_urls).
- gallery_slots가 반환한 extras는 리스트다. 그대로 emit_result에 넣지 말고 ','.join(extras)로 변환한다. 이미 문자열인 값을 다시 문자 단위로 join하지 않는다.
- 추가이미지는 기존 규칙대로 통과한 이미지로 5슬롯을 만든 뒤 순서와 허용된 반복을 그대로 유지해 쉼표 연결한다. 한 줄로 만들기 위해 중복 슬롯을 제거하지 않는다. 유효 이미지가 0개라면 빈 문자열과 사유 로그를 남긴다.
- size/additional_images 미선택이면 수집·결과 포함을 생략한다. 선택된 경우에도 출력 형식 변환을 위해 새로운 네트워크 요청은 필요 없다.
- 현재 Crawler Hub 코드를 수정하는 작업이 아니라, 이 프롬프트로 작성하는 브랜드 코드의 결과 직렬화 규약이다. 실제 최종 Excel에서 사이즈와 추가이미지 셀이 줄바꿈 없이 위 형식인지 검증한다.

[작성 후 검증]
같은 코드로 기본 품번 전체 색상 / 지정 색상 두 구분자 / 하이픈 포함 품번 / 품절 사이즈 / 브랜드·품번 제거 상품명 / 색상코드 없는 사이트를 검증한다. 선택 항목을 모두 끈 경우 전용 요청 함수가 호출되지 않는지도 검증한다. 이미지 검사는 작은 이미지, 10MB 초과, 정상 정지 WebP 통과·손상 파일·정책 미지원 형식, 세로 통짜, 정사각형 콜라주, 사이즈 측정사진, 정상 개별 컷, 후보 0개/1개/여러 개를 포함한다. 샘플과 다른 품번의 정상 갤러리 컷도 통과하는지 확인하며 사전 해시 미등록만으로 탈락하지 않아야 한다. CDN의 실제 파일 형식과 중첩 HTML 정제 오류도 확인한다. 상세에 사이즈표·고시가 정말 없는 상품도 실패하지 않아야 한다. 반대로 원본 고시 값이 존재하는 샘플에서는 원본 항목·값 쌍과 최종 table의 행·값을 대조하고, 0행·값만 비는 현상·표가 아닌 출력이 없는지 검사한다. 소재/관리·배송 구역 및 care 아이콘 전용 요청이 0회인지 확인한다. 일부 색상 실패 후 다른 색상 결과 보존, 품번 FAILED 및 재실행 시 중복 교체를 검증한다. 긴 HTML은 임의 절단 없이 전달하며 공개 URL의 쿠키 의존·HTML 오류·일시 오류를 구분한다. 네트워크 없이 검증한 것과 실제 공식 사이트에서 확인한 것을 구분하여 코드 주석에 짧게 기록한다. 확인하지 못한 상품을 검증 완료라고 쓰지 마라.

최종 답변은 초보자가 정확히 붙여 넣도록 A. 브랜드 정의(JSON), B. 크롤러 Python 코드(Python)를 처음부터 끝까지 분리하여 제공해라.


[브랜드 공유 메모]
관리자에는 브랜드 특이사항·공유 메모란이 있다. 사람이 확인한 등록 환경·이미지 형식 예외·사이트 변경 사항은 여기에 기록할 수 있다. 브랜드 정의의 notes는 문자열이며, 기존 브랜드 메모를 코드 재작성 과정에서 임의로 지우지 않는다. 메모는 Python 실행 코드가 아니며, 실제 검사 조건 변경은 별도 코드 수정으로 구현해야 한다.

[소스별 독립 등록]
사용자가 지정한 수집 대상 소스와 URL만 수집한다. 공식몰 예제 설명을 그대로 믿고 네이버 스토어 입력을 공식몰 주소로 바꾸지 않는다. 네이버 개인/입점 스토어는 해당 스토어 판매 정보임을 구분하고 공식 브랜드 데이터라고 주장하지 않는다. 같은 브랜드 여러 소스는 브랜드명은 같아도 ID, crawl_source, script를 각각 분리한다. 예: 에고이스트 / egoist_official / 공식 홈페이지 / egoist_official.py, 에고이스트 / egoist_nc_ys / 네이버 NC_YS / egoist_nc_ys.py. 상품명 정리에서 제거하는 브랜드명은 소스 표시명이 아닌 실제 브랜드명이다.


[추가 결과 열 — 원본 상품명 등 확장 데이터]
Crawler Hub은 표준 필드에 매핑되지 않은 record 키를 추가 열로 보존한다. 추가 열은 표준 열 뒤에 최초 발견 순서대로 붙는다. JSON output_headers 끝에 "원본 상품명" 같은 열 이름을 선언해도 되고, 선언하지 않고 record["원본 상품명"]으로 전송해도 SDK가 자동으로 열을 추가한다. 열 이름은 비어 있지 않은 문자열이며 공백/표기를 일관되게 사용한다. 일반적인 추가 텍스트 열은 셀에 넣을 문자열로 전달한다. None은 빈 셀, dict는 JSON 문자열, 리스트는 줄바꿈 문자열로 저장되므로 복잡한 값의 출력 형식이 필요하면 크롤러에서 먼저 명시적으로 직렬화한다.
예: record["product_name"] = "융기모 스탠다드 다이마루 팬츠"
    record["원본 상품명"] = "융기모 스탠다드 다이마루 팬츠 TGTM26T01_NC대전유성점"
표준 상품명은 정리하고 원본 상품명은 사이트 문구를 보존한다. 추가 값을 product_name/color/detail_page 같은 다른 표준 필드에 억지로 끼워 넣거나 메모·로그로만 남기지 마라. 표준 선택 항목을 다른 이름의 추가 열에 복제하여 미선택 항목 수집 금지를 우회하지 마라. 표준 필드명으로 인식되는 열 이름은 해당 표준 항목 규칙이 적용된다. 이름에 HTML/대표이미지/추가이미지 등 표준 매핑 표현이 들어가면 매핑될 수 있으므로 독립 텍스트 열은 의미가 분명한 이름으로 지정한다.
수동 매핑은 ctx.emit_unmapped의 record에 같은 추가 키를 넣는다. 원본 URL별 결과와 매핑 후 색상별 결과에 보존된다. 같은 색상에 선택한 사진들의 원본 상품명이 서로 다르면 누락하지 않고 서로 다른 값을 줄바꿈으로 함께 기록한다. 추가 열은 필수/선택 표준 수집 항목과 별개이며 결과 검수의 추가 수집 정보에서도 확인할 수 있다.

[사용자 지정 셀러/지점 조건 — 일반 브랜드명 검사와 구분]
사용자가 쇼핑몰의 특정 셀러/지점만 수집하라고 명시하면 그 조건을 해당 브랜드·소스 크롤러에 한정해 적용한다. 이것은 브랜드명이 상품명에 있어야 한다는 일반 검사가 아니다.
예: 이랜드몰의 NC 유성점 상품만 요청하면 원본 상품명을 정리하기 전에 지점 조건을 검사한다. "NC 유성", "NC유성", "NC대전유성점"처럼 사용자가 요청했거나 실제 판매점 표기로 확인된 명칭만 정규화하여 대조한다. 단순히 NC 또는 유성이라는 낱말 하나만으로 통과시키지 말고 NC 대전유성점과 다른 지점을 혼동하지 마라. 실제 제공된 셀러/판매점 정보도 확인 가능하면 함께 대조한다. 확인되지 않은 지점 별칭을 발명하지 않는다.
NC 유성 조건을 통과한 원본 제목을 "원본 상품명" 추가 열에 보존하고, 표준 product_name에서는 브랜드·공식 품번·해당 지점 표기를 실제 포함된 경우에만 제거한다. 다른 지점 상품은 제외한다. 다른 지점만 검색되어 수집 대상이 없으면 그 사유를 명확히 알린다. 이 조건을 다른 공식몰·셀러 크롤러에 공통 강제하지 마라.

[상품 링크 필수 수집 — product_url]
필수 결과는 product_code(품번), product_name(상품명), color(색상/색상 후보), product_url(상품 링크) 네 항목이다. 브랜드 정의 output_headers에 "상품 링크"를 표준 열로 포함하고 Python record['product_url']에는 실제로 조회·품번 확인에 사용한 상품 상세페이지의 공개 HTTP/HTTPS URL 한 개를 항상 넣는다. 사용자가 입력 엑셀에 링크를 추가해야 한다는 뜻이 아니다. 기본 품번 검색 후 크롤러가 상품 링크를 찾아 수집한다.
상품 링크는 선택 항목/추가 메모가 아니며, 이미지·상세·가격 등을 모두 끈 경우에도 수집한다. 검색 결과 URL, 몰 메인 URL, 이미지 CDN URL, API 응답 URL, 임의 조합한 미확인 URL로 대신하지 마라. 실제 확인된 canonical 상품 주소 또는 조회 후 최종 상품 상세 URL을 사용한다. 인증 토큰·쿠키·일회용 추적정보가 필요한 주소는 쓰지 않는다. 실제 상품 링크를 확인할 수 없으면 명확한 필수 수집 실패로 알린다. 추측한 링크를 만들어 넣지 않는다.
자동 매핑은 각 색상 결과가 나온 상품 상세 링크를 해당 행에 넣는다. 수동 매핑은 원본 사진별 행에 해당 사진을 수집한 상품 링크를 넣는다. 여러 상품 링크의 사진을 먼저 합쳐 공통 output을 만드는 크롤러는 정확한 품번·대상 판매점으로 확인된 첫 번째 상품 링크를 공통 product_url로 넣는다. 색상 매핑 후 재구성할 때 허브는 같은 기본 품번에서 수집 성공한 자료의 첫 번째 상품 링크 하나를 모든 색상 행에 동일하게 적용한다. 선택한 사진의 링크로 바꾸거나 여러 링크를 쉼표/줄바꿈으로 합치지 않는다. 첫 번째 링크가 사진 선택에서 제외되더라도 링크 기준은 유지한다. 실패·미완료 입력 행의 링크는 사용하지 않는다.
크롤러의 모든 emit_result/emit_unmapped 경로에서 product_url이 실제 URL인지 확인한다. 예: record['product_url'] = verified_product_page_url. 일반 추가 열인 원본 상품명·판매점 등의 자동 보존 규칙은 유지한다. '상품 링크'/'공홈링크'/'상품URL'은 이 필수 표준 필드로 인식되므로 중복 추가 열로 취급하지 않는다.
검증: 선택 항목 전체 해제 시에도 링크 전송, 링크 누락/비HTTP 주소 실패, 자동 색상별 링크 보존, 수동 매핑에서 두 링크의 사진 선택 순서를 바꿔도 최종 링크는 최초 링크 하나인지 확인한다.
