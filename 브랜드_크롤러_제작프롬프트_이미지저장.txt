[호환 대상: Crawler Hub v0.8.2 이상 / Level 1. 이미지 저장 SDK는 이 버전 이상에서 새로 시작한 작업에 사용한다.]

Crawler Hub — Level 1 로컬 이미지 저장·크롭·색상 매핑 크롤러 제작 요청

이 파일 전체를 다른 AI에게 전달한다. 아래 작성란만 실제 값으로 바꾼다. 기존 자동 매핑용 프롬프트를 함께 제공할 필요는 없다.

[내가 작성하는 정보]
브랜드 ID: 여기에 영문 소문자·숫자·언더바로 입력 (소스마다 다른 ID)
브랜드명: 여기에 입력
카테고리: 여기에 입력
크롤링 소스: 공식 홈페이지 / 네이버 브랜드 스토어 / 네이버 NC_YS 등
브랜드 몰 또는 스토어 URL: 여기에 입력
시험할 기본 품번 2~3개: 여기에 입력
추가 참고사항 또는 기존 크롤러: 있으면 여기에 첨부

[목표와 작업 범위]
위 사이트용 Python 크롤러와 브랜드 정의 JSON을 완성해라. Crawler Hub의 기존 수동 매핑 기능에 등록할 코드다. 통짜 상세 이미지/공식 페이지 캡처에서 상품 개별 컷을 크롭하여 로컬 JPEG로 저장하는 유형이다. 실제 인식 근거가 있으면 색상을 사전 매핑하고, 그렇지 않은 컷은 미매핑으로 보내 사람이 확인한다. 색감만으로 색상코드를 추측하지 않는다. 허브 UI·서버·SDK 수정, 자체 색상 매핑 화면·Excel 저장·서버·GUI 구현은 필요 없다.
공식 검색·상품 페이지·공개 JSON/API를 실제 조사하고 URL·선택자·응답 필드를 확인해라. 예제 품번만 통과하는 하드코딩을 금지한다. 직접 접속할 수 없다면 필요한 상품 HTML·공개 JSON·샘플 URL을 요청하고, 확인하지 않은 동작을 검증 완료라고 주장하지 마라. 접근 제한을 우회하거나 판매자 로그인·쿠키·인증정보를 코드에 넣지 마라.

[완성 답변 형식과 초보자 붙여넣기 안내]
답변은 반드시 아래 A, B를 분리한다. 서로 섞거나 하나의 Python 파일로 합치지 마라.
A. 관리자 ‘브랜드 정의’에 붙여넣는 JSON: 첫 {부터 마지막 }까지 하나의 유효한 JSON을 제공한다. 주석·설명·생략 기호를 JSON 안에 넣지 마라.
B. 관리자 ‘크롤러 Python 코드’에 붙여넣는 전체 Python: 첫 줄 PORTAL_API_VERSION = 1부터 코드 마지막 줄까지 빠짐없이 제공한다. TODO, pass, 가짜 데이터, 미구현 함수로 끝내지 마라.
각 부분 앞에 붙여넣을 곳을 한 문장으로 안내한다. ```json, ```python, 마지막 ```와 A/B 제목은 입력란에 붙이지 않는다고 설명한다.
관리자 위쪽의 브랜드 ID·브랜드명·카테고리·크롤링 소스 네 칸에 넣을 값도 별도로 안내한다. 브랜드명에 소스나 ‘색상 매핑 필요’를 붙이지 않는다. 허브가 이름 (소스)와 별도 배지를 표시한다.
새 브랜드 코드는 공유폴더 brands/<브랜드ID>.py에 저장된다. JSON script에는 폴더 없이 <브랜드ID>.py만 쓴다. 기존 수정은 관리자에서 해당 브랜드를 먼저 선택하며 기존 script 경로와 공유 메모를 유지한다. 다른 소스의 같은 브랜드를 덮어쓰지 마라.
끝에는 실제 시험한 품번·확인 결과·미확인 범위를 짧게 적는다. 사용자에게 허브 공통 코드를 바꾸라고 요구하지 마라.

[A. 브랜드 정의 필수 규약]
execution_level은 1, mapping_mode는 반드시 "manual", image_mode는 "local", image_color_mapping은 "manual"로 지정한다. 사전 매핑 여부와 관계없이 이 값으로 등록하여 사람이 확인·수정할 수 있게 한다. 허브는 별도의 ‘이미지 저장’ 배지를 표시한다. "automatic" 또는 "verified"로 쓰지 마라.
아래는 구조 예시다. ID·이름·소스·예시·패턴·지원 여부·이유를 실제 조사 결과로 교체한다. 아래 unverified 상태를 조사 없이 supported로 바꾸지 마라.

필수 수집 항목은 품번·상품명·색상 후보·상품 링크다. 선택 항목은 사이즈·가격·카테고리·대표이미지·추가이미지·상세페이지다. 불가능하면 supported=false/status=unsupported/정확한 reason을 제공하여 실행 전 비활성 표시되게 한다. 일부 상품에만 없는 항목은 conditional로 구분한다. 고시나 사이즈표가 일부 상품에 없다는 이유만으로 상세 전체를 불가능하다고 하지 마라.
수동 매핑은 대표 또는 추가이미지 수집 중 하나 이상이 필요하다. 두 이미지 항목이 모두 불가능하면 이 방식 자체가 가능한지 다시 확인한다.
지원 라이브러리는 Python 표준 라이브러리, beautifulsoup4, openpyxl, Pillow, playwright다. requests 등 추가 설치가 필요한 패키지에 의존하지 마라. 브라우저가 꼭 필요할 때만 playwright를 사용하고 설치·실행 조건을 명시한다. 가능한 공개 HTML/JSON 방식부터 조사한다.

[B. Python 실행 계약 — 실제 SDK]
첫 줄은 PORTAL_API_VERSION = 1, 진입점은 def crawl(ctx): 이다. 명칭 PORTAL_API_VERSION은 SDK 호환 식별자이므로 HUB_API_VERSION 등으로 바꾸지 마라.
허브는 입력 엑셀 한 행마다 별도 프로세스로 호출한다. 현재 행은 ctx.item(dict), 품번은 ctx.product_code(str)다. 전체 입력 엑셀을 다시 읽어 반복하지 마라. 반환값으로 결과를 전달하지 않는다.
사용 가능한 메서드는 다음과 같다.
- ctx.enabled(field): 필수·선택 필드 활성 여부. field는 product_code/product_name/color/product_url/size/price/category/main_image/additional_images/detail_page 중 하나다.
- ctx.collect(field, loader): 선택됐을 때만 인자 없는 loader를 실행한다. lambda: fetch()처럼 전달하며 fetch()를 먼저 호출하지 마라.
- ctx.checkpoint(): 일시정지·중지 확인. 요청 전후, 재시도 사이, 상품·사진 반복마다 호출한다.
- ctx.stage("단계 설명"): 진행 단계 표시와 체크포인트.
- ctx.log("설명", "INFO" 또는 "SUCCESS" 또는 "WARNING" 또는 "ERROR"): 단계·URL·제외 이유 기록.
- ctx.fail_item("구체적인 실패 이유"): 현재 입력 행 수집 미완료 기록. 즉시 예외를 던지지는 않으므로 다른 상품 링크의 성공 결과는 보존할 수 있다.
- ctx.save_image(source, crop=None): PIL.Image, 실제 이미지 bytes 또는 이미지 파일 Path를 받아 JPEG 개별 컷으로 로컬 저장하고 Path를 반환한다. crop은 원본 픽셀 기준 정수 (left, top, right, bottom)이다.
- ctx.emit_local_image(record, colors, image_path, mapped_color=None, mapping_evidence="", shared_detail_html=""): 저장한 개별 컷 한 장당 한 번 호출한다. image_path는 ctx.save_image 반환값이다.
- ctx.image_dir는 허브가 정한 작업별 원본 이미지 폴더다. 임의 파일을 쓰지 말고 save_image로 저장한다.
- ctx.output_dir: 사용자 로컬 작업 출력 폴더(Path). 캐시·임시파일은 필요할 때만 이 아래에 저장한다. 공유 소스/브랜드 코드 폴더에 쓰지 마라.
ctx.emit_result는 자동 크롤러용 일반 행 전송에 쓰인다. 이 수동 크롤러에서 emit_result만 호출하면 매핑 메타데이터가 없으므로 사용하지 않는다. SDK 내부 변수 _emit/_unmapped 등을 직접 수정하지 마라. ctx.finish는 허브 worker가 호출하므로 크롤러에서 별도 호출하지 않는다.

[로컬 이미지 SDK 호출 형식 — 실제 존재하는 API만 사용]
record = {
    "product_code": "실제기본품번",
    "product_name": "정리한 실제 상품명",
    "product_url": "https://example.com/실제확인한상품상세페이지"
}
colors = [{"color_name": "IVORY", "color_code": "39"}, {"color_name": "BLACK", "color_code": "19"}]
# 선택됐고 실제로 수집한 경우에만 record에 price/size/category/detail_page를 추가한다.
# 사이즈는 "065,070,075"처럼 쉼표 구분 문자열이다. 원본 상품명 등 추가 키도 보존된다.
saved_path = ctx.save_image(source_image, crop=(left, top, right, bottom))
# 미매핑 사진:
ctx.emit_local_image(record, colors, saved_path, shared_detail_html=record.get("detail_page", ""))
# 또는 실제 텍스트/공식 메타데이터로 색상을 확인한 사진:
ctx.emit_local_image(
    record, colors, saved_path,
    mapped_color={"color_name": "IVORY", "color_code": "39"},
    mapping_evidence="실제로 읽은 원문과 해당 크롭 컷의 연결 근거",
    shared_detail_html=record.get("detail_page", "")
)
위 두 emit 호출은 서로 다른 사용 예다. 같은 사진에 두 번 호출하지 마라. 완성 코드에서는 실제 수집·인식한 값으로 채워라.
source_image는 PIL.Image 객체, 이미지 bytes 또는 로컬 임시 원본 이미지 파일 Path다. URL 문자열을 source_image에 직접 넣지 마라. URL은 크롤러가 제한된 크기·timeout으로 다운로드한 뒤 bytes를 전달한다. Playwright 캡처도 실제 캡처 bytes를 전달한다.
크롭할 필요가 없는 실제 개별 컷은 ctx.save_image(source_image)로 저장할 수 있다. crop 바깥 영역을 자동 흰색으로 채워 가짜 사진을 만들지 않도록 범위를 검증한다. 500px 미만인 컷을 억지로 확대하여 통과시키지 않는다.
허브는 최초 원본을 내용 해시가 포함된 임시 JPEG 이름으로 보존한다. 브랜드 코드는 최종 파일명을 직접 바꾸거나 완료 이미지 폴더를 만들지 마라. 색상 매핑 완료 시 허브가 품번_색상코드.jpg 및 _02.jpg 등 최종 파일명을 생성하고 결과 Excel에는 URL 대신 그 파일명 문자열을 넣는다. 웹 미리보기용 localhost URL·절대 로컬 경로를 Excel에 넣지 않는다.
ctx.emit_unmapped는 공개 URL 방식 전용이므로 이 유형에서는 쓰지 마라. ctx.emit_result만 호출하여 로컬 매핑 메타데이터를 누락시키지도 마라. SDK의 내부 변수·저널·매핑 JSON·파일 내보내기 상태를 직접 수정하지 않는다.
모든 record에는 필수 product_code/product_name/product_url이 있어야 한다. color는 emit_local_image가 실제 후보 목록으로 설정한다. 필수 링크가 없거나 colors가 비어 있으면 명확한 실패로 알린다. 상품 링크는 실제 상품 페이지 URL이고 이미지 결과만 파일명으로 바뀐다.

[사전 색상 매핑과 OCR]
이미지에 찍힌 색상명/색상코드, 그 이미지와 직접 연결된 DOM 텍스트/공식 JSON 등 실제 근거로 해당 컷을 구분할 수 있으면 mapped_color를 전달한다. mapped_color는 colors에 존재하는 실제 옵션과 일치해야 하며 mapping_evidence는 비어 있지 않은 실제 인식 근거 문자열이어야 한다. 색상코드가 있으면 이름과 코드 둘 다 전달한다.
예: 실제 이미지의 "39 IVORY" 라벨을 인식했고 해당 라벨이 어느 컷의 것인지 경계가 확인될 때만 IVORY/39로 연결한다. 다른 사진의 라벨, 배너 문구, 파일명 추측, 사진의 평균 색상만으로 확정하지 않는다. 인식 불확실·라벨 없음·다중 라벨 충돌이면 mapped_color=None으로 보낸다.
허브 자체에 OCR 엔진은 내장되어 있지 않다. ctx.ocr 같은 가상의 API를 만들지 마라. 먼저 사이트에서 실제 제공하는 DOM/JSON 라벨로 확인하고, 픽셀 OCR이 필요하다면 실제 사용할 OCR 라이브러리·엔진·설치 조건을 명시한다. 기본 설치에는 표준 라이브러리, BeautifulSoup, Pillow, openpyxl, Playwright만 있다. 추가 OCR 의존성 없이 확인할 수 없는 경우도 미매핑 사진을 수집하여 사람에게 넘길 수 있게 한다. OCR을 실행하지 않았는데 인식 완료라고 기록하지 마라. 외부 유료 OCR 호출·인증정보를 임의 도입하지 않는다.
사전 매핑한 사진은 화면에서 옵션별 선택과 저장 표시가 미리 적용된다. 나머지 사진은 미선택으로 표시한다. 사용자는 사전 매핑도 바꾸거나 해제하고, 옵션 추가·삭제·초기화와 중간 저장을 할 수 있다. 수집 당시 사전 매핑이 이후 사용자의 수정값을 덮어쓰면 안 된다. 이는 허브가 관리하므로 브랜드 코드가 별도 상태 복구를 구현하지 않는다.

[검색·상품명·색상 후보 규칙]
1. 기본 입력은 색상코드 없는 품번이다. 정확히 일치하는 모든 상품 링크·색상 후보를 수집한다. 품절 상품·품절/disabled 옵션도 접근 가능하면 유지한다. 재고 없음이라는 이유로 생략하지 마라.
2. 지정한 브랜드 몰·스토어를 수집 범위의 기준으로 삼는다. 상품명에 브랜드명이나 별칭이 없어도 정상이다. 특정 브랜드 이름이 들어 있어야 통과하는 검사·assert·정규식을 금지한다. 공식 상품 ID·자체상품코드·품번 필드 등으로 품번을 확인한다. 상품명에 품번이 없더라도 별도 공식 필드로 확인할 수 있으면 허용한다.
3. 출력 상품명은 실제 상품명 부분만 남긴다. 브랜드명·공식 품번이 실제 포함된 경우에만 안전하게 제거한다. 우연히 겹치는 부분 문자열을 무작정 삭제하지 마라.
4. 색상명과 코드를 모두 알면 분리한다. "39 Ivory" 또는 "(39)Ivory"는 이름 Ivory/코드 39, 공식 코드 IV와 옵션명 아이보리는 이름 아이보리/코드 IV다. 둘 중 하나만 있으면 그것만 보존한다. WHITE/WHT/01 등 코드를 추측하지 마라.
5. 여러 링크에서 같은 색상 코드·이름을 수집하면 누락 없이 합친다. 사진 URL이 이미 나왔다는 이유로 뒤 링크의 색상 후보·고시·사이즈표까지 건너뛰지 마라. 모든 링크의 메타데이터를 합친 다음 사진 URL을 중복 제거해 한 저장 후보 JPEG당 한 행을 내보내는 방식을 권장한다. 기본 품번의 표기(대소문자·구분자)는 공식 근거로 일관되게 정규화해 같은 카드로 합쳐지게 한다. 다른 품번을 임의로 합치지는 않는다.
6. 수동 매핑에서는 기본 품번 수집을 우선 지원한다. 색상코드 정보가 있어도 사진과 연결되지 않았다면 품번_색상코드 입력을 지원한다고 광고하지 마라. 색상 지정 입력은 해당 색상 갤러리를 공식 구조로 한정할 수 있다고 실제 확인한 경우에만 추가하고, 기본 품번 전체 색상 수집을 유지한다. 원래 품번의 하이픈을 색상 구분자로 무조건 자르지 마라.
7. 공식 색상 후보가 아예 없으면 임의로 ‘기타’나 추정 색상을 생성하지 않는다. 현재 SDK는 비어 있는 colors를 허용하지 않으므로 명확한 미지원/수집 실패로 알린다. 옵션 추가 UI는 실제 후보가 있는 수집 결과에 빠진 색상을 보완하는 기능이다.

[선택 항목은 요청·파싱 단계부터 생략]
ctx.enabled('price')가 false면 가격 전용 요청과 가격 파싱을 하지 않는다. 사이즈·카테고리·상세에도 동일하게 적용한다. 전부 수집해놓고 출력에서만 제외하는 방식은 금지한다.
기본 상품 페이지의 공용 요청은 필수 품번·상품명·색상 후보를 위해 할 수 있지만, 선택하지 않은 항목의 전용 탭/추가 API/이미지 다운로드/HTML 생성은 실행하지 않는다.
대표 또는 추가가 선택되어 있으면 매핑용 갤러리 전체 후보를 수집한다. 매핑 전에 6장이나 10장으로 자르지 마라. 각 색상의 대표/추가 최종 개수 제한은 사용자가 선택한 뒤 허브가 적용한다.
사이즈 옵션은 선택 시에만 수집한다. 상세가 선택된 경우에는 사이즈 열 미선택이어도 상세에 필요한 공식 사이즈표는 수집한다. 두 자료는 서로 다르다.
색상별 사이즈/가격이 다른데 사진에 색상이 연결되지 않았다면 임의로 한 색상의 값이나 전체 사이즈 합집합을 모든 색상의 사실처럼 내보내지 마라. 현재 허브의 매핑 메타데이터는 색상별 사이즈·가격 dict를 지원하지 않는다. 전 색상 공통 값임을 확인한 필드만 지원하거나 해당 capability를 unsupported로 표시한다.

[원본 수집·개별 컷 크롭·저장 검사]
주된 입력이 통짜/세로 긴 이미지여도 원본이라는 이유로 먼저 버리지 않는다. 원본은 개별 컷을 만드는 재료이며, 최종 대표/추가 후보는 크롭된 개별 사진이어야 한다. 페이지를 스크롤 캡처하는 경우 실제 로딩 완료·원본 크기·상품 이미지 경계를 확인한다. 화면 UI·배송 안내·상품고시·사이즈표까지 함께 캡처한 사진을 대표/추가로 내보내지 마라.
사이트별로 DOM 이미지 경계·공식 이미지 조각·여백/구분선·실제 라벨 등의 근거로 크롭 박스를 결정한다. 예제 상품 하나의 고정 y좌표나 같은 높이로 무작정 등분하여 다른 상품을 자르지 마라. 상품/모델이 중간에 잘리거나 두 사진이 한 컷으로 합쳐지지 않았는지 검증한다. 근거가 부족한 경계는 로그를 남기고 사진을 왜곡·발명하지 않는다. 색상 라벨을 인식할 때에는 원본 라벨과 해당 사진의 연결을 먼저 기록한 다음 최종 상품컷에 불필요한 글자 영역을 제외할 수 있다.
최종 컷은 실제 상품 개별 컷·모델 착용 컷·디테일 사진만 사용한다. 통짜·콜라주·배너·로고 단독·스와치·실측선 도식·상품고시·사이즈표는 대표/추가에서 제외하고 고시/사이즈 자료는 상세에서만 사용한다. 상품 고유 프린트·로고까지 지우거나 생성형 보정을 하지 않는다.
ctx.save_image는 JPEG로 실제 재인코딩하며 투명 배경은 흰색으로 합성한다. 저장 컷은 가로·세로 각각 500px 이상, 실제 JPEG 10,000,000바이트 이하, max(가로,세로)/min(가로,세로)<=1.8 규칙을 통과해야 한다. 이 수치는 프로젝트 검사 정책이며 WING 공식 등록 승인 전체를 보장하지 않는다. 비율만으로 콜라주를 완벽히 구분할 수 있다고 주장하지 않는다. 원본 JPEG/PNG/정지 WebP는 해독 가능하면 크롭 재료로 쓸 수 있다. 확장자만 jpg로 바꾸지 마라. 움직이는 이미지·손상 파일·HTML 오류는 제외한다.
한 품번의 전체 상품 링크를 조사한 뒤 모든 실제 색상 후보와 개별 컷을 누락 없이 보낸다. 사진은 매핑 전에 6장/10장으로 자르지 마라. 최종 사용 개수는 사람의 선택 후 허브가 제한한다. 미선택 이미지 요청/크롭/저장은 실행하지 않는다. 원본/임시 캡처는 ctx.output_dir 아래에서만 만들고 공유폴더에 쓰지 않는다.
현재 save_image는 크롭·실제 파일 규격을 검사하지만 사진 내용 판정·OCR·상품 경계 탐지를 자동으로 해주는 함수는 아니다. 내용과 경계 선택은 실제 브랜드 크롤러에서 구현하고 근거를 남겨라. 색상 미확정만으로 정상 상품 컷을 버리지 않는다. 이미지가 0장이면 매핑할 수 없으므로 수집 미완료를 알린다.

[상세페이지 — 모든 색상 공통, 세 종류만]
공식 상품 상세에 있는 상품 이미지(여러 색상 혼재 허용), 실제 상품정보고시, 공식 사이즈표·표 해석용 치수 그림/단위/짧은 주석만 하나의 HTML로 만든다. 매핑한 사진으로 다시 생성하거나 특정 색상의 선택 사진만 남기지 마라. 사용자가 어느 색상에도 선택하지 않은 사진이 공식 상세 안에 들어 있는 것은 허용한다. 여러 상품 링크면 같은 기본 품번의 필요한 상세를 합치고 동일 이미지/표 중복을 정리한다.
소재 및 관리 방법 전용 섹션, 케어 아이콘, 배송·교환·반품·환불, 사이트 공통 안내, 리뷰, 추천상품, 혜택, 구매 UI는 가져오지 않는다. 허용되는 상품 상세 영역을 정확히 선택한다. 모든 탭을 통째로 모은 뒤 배송 제목 하나만 지우는 식으로 구현하지 마라. 제외 영역의 care_*.gif 전용 요청·404 검사도 하지 않는다.
단, 상품정보고시 내부의 소재·혼용률·취급주의 등 공식 항목은 실제 고시 값이므로 유지한다. 별도 사이즈 가이드/세부정보 탭에서는 고시·사이즈표에 해당하는 부분만 가져온다.
고시는 원본이 table/dl/div/JSON 중 무엇이든 실제 항목명-값 쌍을 추출해 <h3>상품정보고시</h3><table><tbody><tr><th>항목</th><td>실제 값</td></tr>...</tbody></table>의 실제 2열 표로 재구성한다. 값이 비는 표, 제목만 있는 고시, 모든 정보를 한 문단으로 붙인 고시는 금지한다. 원문 항목 순서·단위·원산지·제조년월·연락처를 보존하고 값을 발명하지 않는다. 간결한 테두리·여백으로 읽기 좋게 만든다.
사이즈표는 행/열 머리글·단위·rowspan/colspan을 보존한다. 원래 고시/사이즈표가 없는 상품은 실패시키지 말고 그 부분 없이 상세를 완성한다. 실제로 있었는데 파서가 못 읽은 것과 원래 없는 것을 구분한다.
script/style/주석/iframe/이벤트속성/불필요한 class/id/data 속성·중첩 레이아웃을 제거하고, 텍스트는 html.escape, 상대 이미지 주소는 절대 URL로 처리한다. base64 이미지·긴 인라인 CSS·사이트 전체 HTML을 넣지 마라.
from detail_store import excel_detail 로 compact, overflow = excel_detail(markup)을 호출할 수 있다. Excel 한 셀 한도 32,767자 안에 들어가도록 중복 이미지·표·불필요한 마크업부터 줄인다. 값을 임의 잘라내거나 고시/사이즈표를 삭제하여 성공 처리하지 마라. 정리 후에도 overflow면 명확한 수집 실패로 전달한다. 별도 ‘전체 상세 HTML 다운로드’ 파일로 우회하지 않는다.
완성한 동일 HTML을 record['detail_page']와 emit_local_image의 shared_detail_html에 넣는다. 각 사진마다 별도 색상용 HTML을 만들지 않는다.

[허브가 이미 담당하는 기능 — 크롤러에서 중복 구현하지 마라]
수집 중에는 원본 Excel 결과를 저장한 후보 JPEG 한 개당 한 행으로 만든다. 모든 링크의 같은 품번은 한 카드로 합쳐지고 모든 사진·색상 후보를 표시한다.
사용자가 색상을 고른 뒤 사진 전체를 클릭해 선택·저장한다. 색상명과 코드가 있으면 IVORY (39)처럼 표시한다. 한 색상/마지막 남은 색상의 미배정 사진 일괄 선택, 옵션 수기 추가, × 삭제, 옵션 초기화, 중간 저장하고 나가기, 재실행 후 선택 복구는 허브가 담당한다.
최종 결과는 사진을 선택한 색상당 한 행이다. 어디에도 선택하지 않은 사진과 사진 0장으로 저장한 색상은 최종 대표/추가 결과에서 제외한다. 공식 상세 HTML은 전 색상 공통이다.
선택한 사진의 원래 갤러리 순서에서 첫 사진이 대표 1장, 나머지는 추가 정확히 5칸이다. additional_image_count=5로 지정한다. 대표 파일명은 품번_색상코드.jpg, 나머지 실제 컷은 품번_색상코드_02.jpg부터 _06.jpg까지다. 색상코드가 없으면 실제 색상명을 사용하며 사용자가 옵션 추가로 코드를 보완할 수 있다. 서로 다른 상품/옵션의 파일명이 충돌하면 덮어쓰지 않고 명확한 오류로 알린다. 대표 외 추가 컷은 최대 5개만 사용하고 초과분은 생략한다. 추가가 5장보다 적으면 선택된 유효 컷으로 반복해 5장을 채운다. 유효 컷이 하나뿐이면 대표를 추가에도 재사용한다. 크롤러는 매핑 전에 사진 순서를 임의 색상 추정으로 바꾸거나 후보를 잘라내지 마라.
최종 사이즈·추가이미지는 쉼표 구분 한 줄이다. ‘✓ 매핑 완료 · 수정’ 버튼과 이후 수정도 허브 담당이다. 크롤러가 색상 매핑 파일·완료 상태를 직접 쓰지 마라.

[오류·이어하기·진행상황]
모든 요청에 유한 timeout·응답 최대 크기·제한된 재시도를 둔다. 요청 전후와 대기/루프 중 checkpoint를 호출한다. 셀레니움 등 설치되지 않은 도구나 무한 재시도에 의존하지 마라.
일시 오류와 실제 상품 부재를 구분한다. 정확히 일치하는 상품이 없으면 정상 0행 완료로 숨기지 않는다. 필수 품번/상품명/색상 후보 실패는 fail_item과 예외로 전달한다. 성공한 다른 링크의 후보는 보존하면서 최종 입력 행은 미완료로 남긴다. ERROR 로그만 찍고 정상 종료하지 마라. bare except로 중지 신호까지 삼키지 않는다.
복수 링크의 사진이 중복이어도 모든 링크의 후보 색상과 상세를 먼저 취합한다. 하나의 링크 실패가 다른 링크 성공처럼 숨겨지지 않게 한다.
허브는 완료 입력 행을 건너뛰고 실패·중단 행을 다시 수집하며 해당 행의 부분 결과를 교체한다. 크롤러는 자체 완료 목록·전체 입력 반복·중복 append·별도 Excel 저장을 만들지 마라. 재시도 단위는 입력 엑셀 한 행이고, 같은 품번이 입력에 두 행 있으면 두 행을 임의로 건너뛰지 않는다.

[완료 전 검증 항목]
- 브랜드명이 없는 정상 상품명도 통과, 다른 품번은 제외. 기본 품번으로 모든 정확한 상품 링크·품절 색상 후보 수집.
- 같은 품번의 두 링크 중 사진은 같고 색상만 다른 경우에도 모든 색상 유지. 서로 다른 사진은 전부 후보에 포함. 저장 후보 JPEG당 한 행이며 가짜 색상 배정 없음.
- 공식 색상 코드 앞자리 0 보존, 이름만/코드만 있는 후보 허용, 실제 후보 없는 경우 명확한 실패.
- 미선택 가격/사이즈/상세 전용 요청·파싱·생성이 실행되지 않음. 상세 미선택이면 record에 detail_page도 없음.
- 정상 정지 WebP 허용, 작은 썸네일·손상/HTML 응답·통짜·콜라주·실측 사진 제외, 미리 승인한 해시가 없어도 정상 개별 컷 통과.
- 매핑 전 사진이 10장 이상이어도 모두 emit_local_image로 전달. 최종 대표/추가 제한은 허브에 위임.
- record.detail_page는 모든 색상 공통이며 공식 상세의 여러 색상 사진 포함. 고시 항목/값과 표, 사이즈 단위 보존. 관리/배송/care 전용 요청 없음. 없는 고시/표로 실패하지 않음.
- 일부 링크 실패 시 성공 후보 보존과 입력 행 실패, 중지·재개 체크포인트 동작, HTML 셀 한도 초과의 명시적 실패.
실제 사이트에서 확인한 결과와 fixture/오프라인 검사 결과를 구분해 보고해라. 허브가 없는 환경에서는 위 SDK 계약을 흉내 낸 테스트 컨텍스트로 호출 형식·선택 항목 생략을 확인하고, 실제 허브 화면·최종 Excel 검증을 했다고 주장하지 마라.

[로컬 파일 유형 추가 확인]
- 사전 매핑 근거 있는 컷/없는 컷을 섞어 수집한다. 이미 연결된 컷은 해당 옵션에 저장된 상태, 나머지는 미선택으로 나타나는지 확인한다.
- 사람의 색상 수정·해제·중간 저장·앱 재시작 뒤 선택이 유지되고 원본 사전 매핑으로 되돌아가지 않는지 확인한다.
- 최종 파일명과 Excel 대표/추가 셀의 파일명이 정확히 일치하는지, 대표 1장·추가 정확히 5칸 규칙과 부족 시 선택된 파일명 반복이 적용되는지 확인한다.
- 색상을 바꿔 재구성하면 새 파일명으로 다시 생성되며 원본 크롭 파일은 보존되는지 확인한다. 어느 색상에도 선택하지 않은 파일은 등록용 폴더/ZIP에서 제외한다.
- 파일명에 경로 문자/쉼표/제어문자를 넣어 탈출하거나 서로 다른 파일을 덮어쓰지 않는다. 선택되지 않은 원본을 내보내지 않는다.
- 결과 검수에서 로컬 이미지가 보이고 ‘대표이미지 폴더 열기 / 추가이미지 폴더 열기’ 또는 ‘이미지+엑셀 ZIP’으로 실제 등록용 파일을 얻을 수 있다. 후보 원본 폴더 대신 완료 후 등록용 폴더의 이미지를 WING에 업로드한다.
- 대표/추가 셀은 파일명이고 상품 링크는 HTTP/HTTPS URL이다. 상세 HTML에는 localhost 미리보기 URL·절대 파일 경로를 넣지 않는다. 사이트의 기존 공통 상세 HTML 규칙과 사이즈 그림→표 순서는 유지한다. WING에 확인되지 않은 로컬 상세 HTML 참조 문법을 만들어내지 않는다.
실제 사이트가 지정되지 않은 상태에서 크롭 규칙이나 OCR 결과를 완성됐다고 주장하지 말고, 사용자가 위 작성란의 실제 URL·품번을 제공한 뒤 조사해 구현한다.

[필수 링크·추가 열·상세 순서 보완 규약]
상품 링크 product_url은 필수다. 실제 품번 확인에 사용한 상품 상세페이지 HTTP/HTTPS URL을 매 emit_local_image 호출에 넣는다. 이미지 파일명과 상품 링크를 혼동하지 마라. 같은 품번의 여러 링크를 합쳐 공통 record를 만들면 첫 번째 확인 링크 하나를 product_url에 넣는다. 최종 색상별 결과도 수집 성공한 첫 링크 하나를 공통으로 쓰며, 선택한 사진 때문에 링크 기준을 바꾸지 않는다. 검색 URL/몰 메인/API URL/이미지 URL을 상품 링크로 넣지 않는다.
원본 상품명·판매점 등 추가 값은 record["원본 상품명"]처럼 의미 있는 키로 전달한다. 헤더 미선언 키도 SDK가 추가 열로 만들어 표준 열 뒤에 보존한다. 상품명은 정리하고 원본 상품명은 원문을 유지한다. 추가 필드를 로그로만 남기거나 표준 열에 억지로 합치지 마라. 수동 매핑 후 선택 사진의 추가 값이 서로 다르면 서로 다른 값들을 줄바꿈으로 함께 보존한다.
사용자가 NC 유성점 등 특정 셀러/지점 조건을 지정하면 그 소스의 크롤러에만 적용한다. 상품명에 브랜드명이 없다고 제외하는 일반 검사와 구분한다. 지점 검사는 원본 제목에서 실제 확인된 지점 표기를 기준으로 하고, 검사 후 표준 상품명에서 브랜드/품번/해당 지점 표기를 제거한다.
상세 사이즈 가이드는 ‘실제 측정 그림 → 해당 사이즈표 → 단위·짧은 주석’ 순서다. 원본 DOM에서 표가 먼저여도 관련 그림을 표 바로 앞에 배치한다. 여러 표는 각각 대응 그림과 묶고, 없는 그림/표를 만들지 않는다.
실패·미완료 입력 행은 매핑 및 최종 재구성에서 제외하며 다른 성공 품번의 매핑 완료를 막지 않는다. 실패 이력과 재실행 대상은 유지한다.

[등록용 폴더와 바로가기]
등록용 이미지 내보내기는 대표이미지/ 와 추가이미지/ 두 폴더다. 각 폴더 안에 모든 품번·색상의 해당 JPG가 바로 들어가고 품번/색상 하위 폴더를 만들지 않는다. 같은 이름의 이미지가 대표와 추가 양쪽에 필요하면 각 폴더에 복사한다. 대표 외 선택 컷을 우선 쓰고 부족하면 그 추가 컷을 반복하여 셀에 5개를 쉼표로 기록한다. 대표 외 컷이 하나도 없으면 대표 파일명을 5번 반복하고 실제 파일도 추가이미지 폴더에 복사한다. 반복 셀 개수만큼 별도 사본 파일을 만들 필요는 없다. 허브 결과 검수에는 두 폴더 바로가기 버튼을 제공한다. ZIP은 result.xlsx와 images/대표이미지/, images/추가이미지/를 포함한다. 내부 원본/임시 OCR 폴더는 등록용 출력으로 안내하지 않는다.

[선택 기능: 공통 상세이미지를 파일명으로 출력]
필요하면 ctx.save_detail_image(source, source_metadata="원본 출처·권리안내")로 긴 상세 JPEG를 저장할 수 있다. 대표/추가 컷의 비율 제한은 상세 전체 이미지에는 적용하지 않으며 실제 JPEG·파일 용량·픽셀 수는 검사한다.
완성 상세는 ctx.emit_local_image(..., detail_image_path=저장한Path)로 전달한다. SDK가 원본 후보 파일과 메타데이터를 보관하며 최종 매핑 완료 시 상세이미지/품번.jpg로 한 번만 내보낸다. 색상코드로 나누지 않고 같은 품번의 모든 색상 행에 같은 파일명을 출력한다. 이 경우 output_headers에는 '상세페이지'를 사용한다. 웹 미리보기 URL은 엑셀에 넣지 않는다. 필수 품번·상품 링크와 나머지 선택 항목은 기존 규칙을 유지한다.
예를 들어 웨스트우드처럼 제품 전용 통이미지가 있는 경우 색상명 첫 시작~마지막 제품사진까지를 하나의 영역으로 유지하고, 제품 세부이미지 영역, PRODUCT INFO~SIZE 전체 패널을 차례로 아래에 이어 붙인다. '블랙→블랙사진→화이트→화이트사진' 순서를 원본 그대로 보존하고 색상명끼리 먼저 모으지 않는다. 원본 경계와 실제 표제를 확인하며, 단위·모든 표 행·측정 그림을 잘라먹지 않는다. JPEG 원본 출처 및 권리정보는 source_metadata와 결과의 추가 열에 보존한다. 원래 선택되지 않은 상세이미지는 만들지 않는다.
허브에는 상세이미지 폴더 열기와 상세이미지 파일명 복사를 제공한다. 결과 ZIP에는 상세이미지 폴더도 포함된다. 기존 URL/HTML 상세 방식을 쓰는 다른 브랜드의 구현을 강제로 파일명 방식으로 바꾸지 않는다.

최종 상세 구성: 색상명+해당 상품사진(원래 순서) → 제품 세부이미지 → PRODUCT INFO+SIZE. 세 영역을 모두 포함합니다. 파일명은 품번.jpg이며 색상코드를 붙이지 않습니다.
